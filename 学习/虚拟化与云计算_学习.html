1 模块1 虚拟化的基础概念（它到底是什么）

1.1 什么是虚拟化：一栋大楼隔成很多套间

虚拟化 = 用软件在一台真实电脑（物理服务器）上“隔”出多台互相独立的虚拟电脑（虚拟机），每台都能装自己的系统、跑自己的程序。

生活类比：一台物理服务器像一栋大公寓楼，虚拟化把它隔成很多独立小套间（虚拟机）。每户独立水电、独立门锁、互不打扰——你不用为每户单独买一栋楼，一栋楼就能住很多人。这就是虚拟化最值钱的地方：一套硬件，多台“电脑”。

1.2 为什么要“虚拟存储器”（重点，对应 Q1 / Q13）

程序运行时需要内存，但物理内存有限（比如 8G），程序可能想要 16G。操作系统用硬盘的一部分当“扩充内存”（页文件 / 交换分区），让程序以为自己有超大连续的可用空间——这叫虚拟存储器，它的目的是扩大用户的地址空间。

生活类比：书桌（内存）太小、书（程序）太多，把暂时不看的摞到地上大书箱（硬盘）里，需要时再拿上来。书箱让你“能用的书”远超书桌容量——这就是扩大地址空间。注意：书箱不是让你看得更快（不提速），也不是让书变多（不扩硬盘容量），只是让你“能摊开的书”更大了。
⚠ 高频陷阱：虚拟存储器不提高存取速度（硬盘比内存慢）、不扩大外存容量，只扩大“逻辑地址空间”。题目问“目的”→ 选“扩大用户的地址空间”（C）。

2 模块2 虚拟化的三大核心特性（隔离 / 兼容 / P2V）

2.1 隔离特性（对应 Q10）

隔离（Isolation）：一台物理机上的多台虚拟机彼此独立、互不可见、互不干扰。一台中病毒、死机、被攻击，不会波及同主机其他虚拟机。

生活类比：公寓的防火隔墙和隔音墙——邻居家着火或吵闹，不会烧到你家或吵到你。隔离让“共享硬件”却“互不相干”，安全性和稳定性都更高。

2.2 兼容特性（对应 Q12）

兼容（Compatibility）：虚拟化层（hypervisor）把底层硬件抽象成统一的标准设备，于是 Windows、Linux 等多种客户机系统、驱动、老应用都能在同一台物理机上跑。

生活类比：万能转接头——老电器（老系统 / 老应用）也能插上新插座（新服务器）继续用，不必为每种电器配专门插座。

2.3 P2V：把物理机“搬”成虚拟机（对应 Q2 / Q14）

P2V（Physical-to-Virtual）＝把一整台物理服务器整体转换为虚拟机。易混点：把虚拟机在物理机之间迁移叫 V2V（或 vMotion），那不是 P2V。

⚠ 易混点：P2V 方向是 物理机 → 虚拟机。题干若说“把运行中的虚拟机从一台物理机迁到另一台”，那是 V2V / 迁移，不是 P2V → 判断为“错误”。
生活类比：P2V＝把实体店整体改造成网店；V2V＝网店之间搬家。方向不同，别搞反。

3 模块3 VMware 虚拟化平台（vSphere 全家桶）

3.1 vSphere 软件堆栈：三层结构（对应 Q5）

vSphere 从上到下三层：接口层（人 / 程序怎么发命令：Web、命令行、SDK）→ 管理层（vCenter Server 集中调配）→ 虚拟化层（ESXi 真正分割硬件、跑虚拟机）。

生活类比：一家工厂＝车间（虚拟化层，真干活跑虚拟机）+ 厂部（管理层，统一排产调配）+ 接单窗口（接口层，对外接活）。三层各管一摊。

3.2 vSphere 虚拟化层的两种服务（对应 Q3）

虚拟化层向上提供两类服务：基础架构服务（Infrastructure Services，管底层资源：计算 CPU / 内存、存储 VMFS、网络虚拟交换机）+ 应用程序服务（Application Services，给虚拟机提供高可用、安全、容错等）。

3.3 ESXi 与 vCenter：单机 vs 中央大脑（对应 Q7 / Q11）

ESXi 装在单台服务器上，直接跑虚拟机；vCenter Server 是跨主机的“中央大脑”，统一配置、部署、监控，提供 vMotion（迁移）、HA（高可用）、DRS（负载均衡）等集群能力。

⚠ 没有 vCenter 也能做的事：单台 ESXi 本地就能创建虚拟机、给虚拟机设单机警报。而“迁移运行中的虚拟机”（vMotion）和“克隆”依赖 vCenter 集中能力，单机做不了。

4 模块4 高可用与可用性（vSphere 能 / 不能）

4.1 vSphere 解决的 vs 不能解决的（对应 Q4）

vSphere 解决的可用性难题：硬件维护不中断业务（计划内停机零影响）、故障后把虚拟机迁走。
vSphere 不能解决的：灾难恢复变得更复杂、单纯“部署更多服务器”不是它的方案、故障“即将发生前主动迁移”这种表述（真实是故障发生后 vMotion 迁移，或 FT 持续双运行）。

生活类比：双发动机飞机，一台坏了可切另一台继续飞（vSphere 能解决）；但飞机撞山它救不了（灾难恢复等它解决不了）。题目问“不能解决”的，就找这些它搞不定的表述。
⚠ 做题关键：先找“能解决”的（如“维护不中断业务”）排除掉，剩下的就是“不能解决”的→ 本题选 ABD。
Q4. vSphere 不能解决的可用性难题是()。（多选）
▸ 显示解析
🎯 答案解析：选 ABD。A 灾难恢复更复杂、B 堆服务器、D 故障前主动迁移，都是它搞不定的。 📚 知识点讲解：vSphere 能解决“维护不中断”（C），不能解决灾难恢复变复杂、单纯堆机器等。 💡 解题思路：先排除“能解决”的 C，剩 A/B/D 选之。 🧠 记忆口诀：“vSphere 能维护不停机，灾难恢复堆机器它不行。”

5 模块5 虚拟机存储（数据放哪）

5.1 VMware 支持的数据存储类型（对应 Q8）

虚拟机文件（.vmdk 等）放在“数据存储”上。VMware 原生支持两种：VMFS（VMware 自家虚拟机文件系统，块存储）和 NFS（网络文件系统，挂远端存储）。EXT4（Linux 本地）、NTFS（Windows 本地）是操作系统本地文件系统，不能直接当 VMware 数据存储。

生活类比：数据存储＝停车场。VMFS / NFS 是正规对外车位（VMware 认）；EXT4 / NTFS 是自家车库（操作系统本地用），不能当公共停车场停虚拟机。
Q8. 创建虚拟机后，虚拟机被部署在数据存储上。以下哪种类型的数据存储受支持?()（多选）
▸ 显示解析
🎯 答案解析：选 AC。VMware 支持 VMFS 和 NFS 两种数据存储。 📚 知识点讲解：EXT4 / NTFS 是操作系统本地文件系统，不能直接当 VMware 数据存储。 💡 解题思路：认 VMware 自家格式 VMFS，加网络存储 NFS→选 AC。 🧠 记忆口诀：“VMware 存储：VMFS 加 NFS，EXT4 / NTFS 不算。”

6 模块6 云计算（虚拟化的“对外服务版”）

6.1 云计算的特点（对应 Q6）

云计算＝把计算资源当“水电”一样按需租用。特点：服务可租用（A）、高性价比按需付费（B）、服务可计量（D “服务可计算”＝按使用量计费）。“低使用度”（C）不是特点——云恰恰追求高利用率。

生活类比：自家打井（传统 IT）vs 用自来水（云）——用多少付多少，不自己盖水厂。云就是“IT 自来水”。

6.2 云服务三层模型（对应 Q9）

层次全称给你什么生活类比
IaaS基础设施即服务虚拟机 / 网络 / 存储毛坯房 + 水电，自己装修
PaaS平台即服务运行环境 / 数据库平台装修好待入住的房
SaaS软件即服务直接能用的软件拎包入住的酒店
⚠ 注意：BaaS（后端即服务）不是标准三大类之一，本题不选 D。
Q6. 云计算的特点包括以下哪些方面()（多选）
▸ 显示解析
🎯 答案解析：选 ABD。可租用、高性价比、可计量（可计算）。 📚 知识点讲解：“低使用度”与云高利用率相反，不是特点。 💡 解题思路：排除 C“低使用度”→选 ABD。 🧠 记忆口诀：“云特点：可租用、高性价比、可计量。”

核心概念速记

  • 虚拟化：一套硬件隔出多台虚拟机（公寓隔套间）
  • 虚拟存储器目的：扩大用户地址空间（不提速、不扩硬盘）
  • P2V：物理机→虚拟机；虚拟机间迁移是 V2V
  • 隔离：同机虚拟机互不影响；兼容：多 OS 一机跑
  • vSphere 三栈：虚拟化层 + 管理层 + 接口层
  • 虚拟化层两类服务：基础架构服务（计算/存储/网络）+ 应用程序服务
  • ESXi 跑虚拟机；vCenter 中央大脑（无它也能建虚机、设警报；不能迁移/克隆）
  • vSphere 能：维护不中断；不能：灾难恢复变复杂、堆服务器
  • 数据存储：VMFS + NFS（EXT4/NTFS 不算）
  • 云特点：可租用、高性价比、可计量（非低使用度）
  • 云服务三层：IaaS → PaaS → SaaS
