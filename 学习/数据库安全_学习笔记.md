# 数据库安全（61 题）零基础学习笔记

> 面向对象：零基础学习者。按「知识点讲解（通俗类比）→ 配套练习题（含四要素解析）→ 全部题目收尾」组织，学完即可轻松完成配套练习。

> **本章结构提醒**：61 题名为“数据库安全”，实际分三层——真正的安全题约 10 题（模块②的 SQL 注入三考法、隔离装置、配置存储、默认密码，以及模块①的授权与加密）；Oracle DBA 运维题约 30 题（索引、约束、视图、游标、PL/SQL、表空间、分区、归档日志）；完全跑题的灌水题 14 题（Word/Excel/HTML/编译符号表/编码风格/媒体分类，全在模块⑦，已标 edge）。

## ① 数据库基础概念与安全模型

- **关系模型是地基**：关系模型＝二维表，表与表之间靠**公共属性（外键）**联系（题 19）。类比：两张 Excel 表用“学号”这一列关联。对比：层次模型＝树形（组织架构）、网状模型＝图形（指针链接）。**SQL Server、Oracle、MySQL** 都是典型的关系型数据库产品（题 48 判正确）。
- **“字段”是本章两个“最小”的答案**（配对记忆）：**关系运算**的最小单位是**字段**（题 50，因为投影操作就是选列）；**加密**的最小单位也是**字段**（题 51，只加密身份证号、密码等敏感列）。层次顺序：数据库 > 表 > 记录（行） > 字段（列）。
- **数据独立性分两级**：**物理独立性**＝内模式（存储结构）变，模式不变；**逻辑独立性**＝**模式变，用户程序不变**（题 7 选 D）。而**视图**正是实现逻辑独立性的核心手段，所以说“视图不支持逻辑独立性”是错的（题 49 判错误）。
- **数据库安全三支柱**：①**授权粒度**——数据对象**范围越小**（粒度越细）授权越灵活，但系统开销越大（题 12 选 B）；②**静态授权**＝隐性授权——用户对自己拥有的数据自动有全权，无需显式授权（题 52 判正确）；③**权限分配**用**权限校验矩阵**表示——行是用户、列是对象、格子里写权限（题 54 选 B）。
- **安全措施边界**：安全措施＝用户标识与鉴别、存取控制、视图、审计、数据加密；**并发控制属于事务管理，不是安全措施**（题 40 选 D）。**加密特点**：数据库加密不能简单采用对称密钥（需多级/混合密钥体制），且库名/表名/记录名/字段名应各有子密钥（题 53 选 C 为“描述错误”）。
> ⚠ 配对记忆：题 50 与题 51 答案都是“字段”；题 7 逻辑独立 vs 物理独立看“变的是模式还是存储”。

### 本模块练习题

### 7. 在数据库系统中，当数据库的模式改变时，用户程序可以不做改变，这是数据的()。
- 选项：A.位置独立性　B.存储独立性　C.物理独立性　D.逻辑独立性
- 答案：D
- 🎯答案解析：选 <b>D（逻辑独立性）</b>。数据库的模式（逻辑结构）改变时，用户程序可不变，这是数据的逻辑独立性。
- 📚知识点讲解：数据独立性分两级：①<b>物理独立性</b>＝<b>内模式</b>（存储结构）改变时，模式可不变（如换硬盘、改索引、改文件组织方式），用户程序不受影响；②<b>逻辑独立性</b>＝<b>模式</b>（逻辑结构，如表结构、字段）改变时，外模式/用户程序可不变（如加字段，老程序仍能跑）。类比：物理独立性＝换仓库货架但货架编号不变；逻辑独立性＝调整货架编号但给客户看的目录不变。
- 💡解题思路：抓“模式改变 + 用户程序不变”→ 逻辑独立性，选 D。
- 🧠记忆口诀：模式变程序不变是逻辑独立；存储变模式不变是物理独立；题干说模式改，D 选逻辑记心里。


### 12. 在数据库的安全性控制中，为了保护用户只能存取他有权存取的数据。在授权的定义中，数据对象的(),授权子系统就越灵活。
- 选项：A.范围越大　B.范围越小　C.约束越细致　D.范围越适中
- 答案：B
- 🎯答案解析：选 <b>B（范围越小）</b>。数据对象的范围越小（授权粒度越细），授权子系统越灵活。
- 📚知识点讲解：授权粒度：可以粗到整个数据库、某张表，也可以细到某一行、某一列、甚至某个字段的特定值。粒度<b>越细</b>（范围越小），能表达的权限组合越多，授权越灵活；但代价是<b>系统开销越大</b>（权限表膨胀、每次访问都要查更多条目）。类比：门禁权限——整栋楼一个权限最省事但最粗；精确到每个房间每个时段最灵活但管理成本高。
- 💡解题思路：授权粒度越细越灵活 → 范围越小，选 B。
- 🧠记忆口诀：授权粒度越细越灵活，范围越小权越精；但开销随之涨，B 选范围小记分明。


### 19. 在数据库技术中，哪一种数据模型是使用公共属性(外键)实现数据之间联系的()。
- 选项：A.面向对象模型　B.关系模型　C.网状模型　D.层次模型
- 答案：B
- 🎯答案解析：选 <b>B（关系模型）</b>。关系模型用公共属性（外键）实现表与表之间的联系。
- 📚知识点讲解：三种传统数据模型：①<b>层次模型</b>＝树形结构，父子节点联系（如组织架构）；②<b>网状模型</b>＝图形结构，节点间多对多联系用指针/链路实现；③<b>关系模型</b>＝二维表，表间联系靠<b>公共属性（外键）</b>——一张表的主键出现在另一张表中作外键。类比：关系模型像两张 Excel 表用“学号”这一列关联。
- 💡解题思路：抓“公共属性（外键）”→ 关系模型，选 B。
- 🧠记忆口诀：层次像树网像图，关系二维表用外键；公共属性做桥梁，B 选关系模型来。


### 40. 数据库系统一般都会提供一系列安全措施，以下不属于数据库安全措施的是()。
- 选项：A.用户标识与鉴别　B.视图和触发器　C.存取控制　D.并发控制
- 答案：D
- 🎯答案解析：选 <b>D（并发控制）</b>。并发控制属于事务管理与完整性范畴，不属于数据库安全措施。
- 📚知识点讲解：数据库<b>安全措施</b>主要包括：用户标识与鉴别（你是谁）、存取控制（你能干什么）、视图机制（只给你看该看的）、审计（记录你干了什么）、数据加密（看不懂）。而<b>并发控制</b>解决的是多个事务同时操作时的<b>数据一致性</b>问题（丢失修改、脏读、不可重复读），属完整性/事务管理范畴，不是安全措施。
- 💡解题思路：找“不属于安全措施”→ 并发控制是事务管理，选 D。
- 🧠记忆口诀：安全措施有五样，标识鉴别存取视图审计加密；并发控制管一致性，D 不属于要记清。


### 48. SQL Server 2000 是典型的关系型数据库产品。
- 选项：A.正确　B.错误
- 答案：正确
- 🎯答案解析：判 <b>正确（A）</b>。SQL Server 2000 是微软的典型关系型数据库产品。
- 📚知识点讲解：常见关系型数据库（RDBMS）产品：<b>Oracle</b>、<b>SQL Server</b>（微软）、<b>MySQL</b>、<b>PostgreSQL</b>、<b>DB2</b>（IBM）、<b>Access</b>。它们都用二维表组织数据、支持 SQL 语言、用外键建立表间联系（呼应题 19 关系模型）。
- 💡解题思路：表述符合事实，判正确。
- 🧠记忆口诀：关系数据库六大家，Oracle、SQL Server、MySQL、PostgreSQL、DB2、Access；SQL Server 2000 是其中，正确判来不复杂。


### 49. SQL 语言的视图定义和视图操作功能不支持逻辑数据的独立性。
- 选项：A.正确　B.错误
- 答案：错误
- 🎯答案解析：判 <b>错误（B）</b>。SQL 的视图定义和视图操作功能<b>支持</b>逻辑数据独立性。
- 📚知识点讲解：视图是逻辑独立性的<b>核心实现手段</b>（呼应题 7、题 16）：当数据库的逻辑结构（模式）变化（如拆表、加字段）时，可以通过修改视图定义，让用户的查询（外模式）保持不变。所以视图<b>支持</b>逻辑独立性，题干说“不支持”是错的。
- 💡解题思路：抓“不支持”→ 视图恰恰是支持逻辑独立性的关键，判错误。
- 🧠记忆口诀：视图支持逻辑独立，模式变了改视图；用户查询仍不变，说不支持判错误。


### 50. 数据库关系运算中参与运算的最小单位是()。
- 选项：A.数据库　B.表　C.字段　D.记录
- 答案：C
- 🎯答案解析：选 <b>C（字段）</b>。数据库关系运算中参与运算的最小单位是字段。
- 📚知识点讲解：与题 51 配对记忆：<b>关系运算</b>的最小单位是<b>字段</b>（列/属性）；<b>加密</b>的最小单位也是<b>字段</b>。关系运算（选择、投影、连接）中，投影操作就是“选某些列（字段）”，所以字段是最小操作对象。层次从大到小：数据库 > 表 > 记录（行） > 字段（列）。
- 💡解题思路：抓“最小单位”→ 字段，选 C。
- 🧠记忆口诀：关系运算最小是字段，加密最小也是字段；库表记录字段四层，C 选字段最下面。


### 51. 数据库中最小的加密单位是()。
- 选项：A.字段　B.数据库　C.记录　D.表
- 答案：A
- 🎯答案解析：选 <b>A（字段）</b>。数据库中最小的加密单位是字段。
- 📚知识点讲解：呼应题 50——<b>加密粒度</b>由粗到细：整个数据库 > 表 > 记录 > <b>字段</b>。<b>字段级加密</b>最细：只加密敏感列（身份证号、银行卡号、密码），其他列保持明文，兼顾安全性与查询效率。类比：保险柜只锁贵重抽屉，不是把整个房间封死。
- 💡解题思路：抓“最小加密单位”→ 字段，选 A。
- 🧠记忆口诀：加密粒度四层递，库表记录到字段；只加密敏感列最灵活，A 选字段记心间。


### 52. 一般意义上，可以把对数据库用户的静态授权理解为 DBMS 的隐性授权。即用户或数据库管理员对他自己拥有的数据，不需要有指定的授权动作就拥有全权管理和操作的权限。
- 选项：A.正确　B.错误
- 答案：正确
- 🎯答案解析：判 <b>正确（A）</b>。静态授权可理解为 DBMS 的隐性授权。
- 📚知识点讲解：授权两种方式：<b>静态授权（隐性授权）</b>＝用户对自己创建/拥有的数据对象<b>自动拥有</b>全部权限，无需显式授权（你建的表你自动能增删改查）；<b>动态授权（显式授权）</b>＝需要 DBA 或属主用 <b>GRANT</b> 语句<b>显式授予</b>他人权限（呼应题 12 授权粒度）。
- 💡解题思路：表述符合静态授权/隐性授权的定义，判正确。
- 🧠记忆口诀：静态授权是隐性，自己的数据自动有全权；动态授权靠 GRANT，显式授予才可行。


### 53. 下列关于数据库加密的应用特点描述错误的是()。
- 选项：A.数据库关系运算中参与运算的最小单位是字段　B.数据库数据是共享的　C.数据库密码系统应采用对称密钥　D.库名、表名、记录名、字段名都应该具有各自的子密钥
- 答案：C
- 🎯答案解析：选 <b>C（数据库密码系统应采用对称密钥）</b>。该描述错误。
- 📚知识点讲解：数据库加密的应用特点：①关系运算最小单位是字段（A 对，呼应题 50）；②数据是<b>共享</b>的（B 对，多用户访问，加密不能破坏共享性）；③库名/表名/记录名/字段名都应各有子密钥（D 对，分级密钥管理）；④<b>不能简单采用对称密钥</b>（C 错）——数据库数据共享、多用户、密钥管理复杂，通常采用<b>多级/混合密钥体制</b>（用公钥密码保护密钥、对称密码加密数据），单一对称密钥无法满足灵活的权限分发与密钥管理需求。
- 💡解题思路：找“描述错误”→ C 说应采用对称密钥，过于绝对，选 C。
- 🧠记忆口诀：数据库加密四特点，字段最小数据共享，各级对象各有子密钥；不能简单用对称密钥，C 描述错误选中它。


### 54. 数据库中的权限分配在数据库中可以用()表示。
- 选项：A.权限向量　B.权限校验矩阵　C.权限点　D.权限图型结构
- 答案：B
- 🎯答案解析：选 <b>B（权限校验矩阵）</b>。数据库中的权限分配可用权限校验矩阵表示。
- 📚知识点讲解：存取控制机制中的<b>授权矩阵（权限校验矩阵）</b>：<b>行</b>＝用户/主体，<b>列</b>＝数据对象/客体，<b>单元格</b>＝该用户对该对象的操作权限（读/写/删/改）。DBMS 每次访问都查这个矩阵（或其压缩形式：按行存为“能力表”、按列存为“访问控制表 ACL”）。类比：像一张门禁权限表，横是员工、竖是房间、格子里打勾。
- 💡解题思路：权限分配用矩阵表示 → 权限校验矩阵，选 B。
- 🧠记忆口诀：权限分配靠矩阵，行是用户列是对象；格子里面写权限，B 选校验矩阵强。



## ② 事务并发与 SQL 注入防护（本章安全核心）

- **SQL 注入三考法**（本章最重要考点）：①**怎么防**——参数化查询（最有效，让 SQL 结构与数据分离）、输入过滤、输入有效性检查；而“**对用户输出进行处理**”防的是 XSS 不是注入（题 6 选 B）；②**危害有哪些**——看改删数据、访问系统表、提权到 DBA；而“控制受害者机器攻击其他网站”是僵尸网络的危害不是注入（题 34 选 D）；③**类型检查能防吗**——能！固定类型的字段（如纯数字 ID）强制校验类型，注入 payload 带的引号直接被挡（题 55 判正确）。
- **隔离装置的 SQL 防护**：默认严格模式阻断**对数据库的一切管理操作**——建删用户、建删存储过程、建删表空间都禁；而“配置策略”是隔离装置**自身**的配置，不在禁止之列（题 13 选 D）。呼应“网络攻击类型”章题 21（逻辑强隔离四功能）。
- **配置存储安全四要求**（题 27 全选）：放对地方（别放 Web 目录）、不明文存储、加密 + 访问控制、变更要授权且留痕。类比：保险柜放内室、钥匙不挂门上、只有经理能开、每次开都登记。
- **默认密码必须改**（题 61）：Oracle 四大默认账号——**sys / change_on_install**（最高权限）、**system / manager**、**scott / tiger**、**aqadm / aqadm**。记忆妙招：sys 的密码字面意思就是“安装后请改掉”。
- **事务与死锁**：事务是数据库运行的**基本单位**，ACID 四性——原子性（要么全做要么全不做）、一致性、隔离性、持久性（题 36 判正确）。**死锁只在并发时才可能出现**（题 39 选 B）——多事务竞争资源形成循环等待；解决靠超时、死锁检测回滚、约定加锁顺序，而不是禁止并发。
> ⚠ 三处“找不同”：题 6 找“不能防”（输出处理）、题 34 找“不是危害”（控制机器）、题 40 找“不是安全措施”（并发控制）。

### 本模块练习题

### 6. 下列方法()不能有效地防止 SQL 注入。
- 选项：A.对用户输入进行过滤　B.对用户输出进行处理　C.使用参数化方式进行查询　D.检查用户输入有效性
- 答案：B
- 🎯答案解析：选 <b>B（对用户输出进行处理）</b>。处理“输出”防不了 SQL 注入——注入发生在“输入进入 SQL 语句”的环节。
- 📚知识点讲解：防 SQL 注入的正确做法：①<b>参数化查询（预编译 / PreparedStatement）</b>——最有效，让 SQL 结构与数据分离，输入永远当数据不当代码（呼应“网络攻击类型”章题 17 转义字符）；②<b>输入过滤</b>（过滤/转义特殊字符如单引号、分号）；③<b>输入有效性检查</b>（类型、长度、格式白名单）。而“对用户<b>输出</b>进行处理”（如 HTML 转义）是防 <b>XSS 跨站脚本</b>的手段，不是防注入。类比：注入是“坏人往菜里下毒”（管输入），输出处理是“端上桌前再检查”（防的是另一类问题）。
- 💡解题思路：找“不能防注入”→ 处理输出管不了输入环节，选 B。
- 🧠记忆口诀：防注入抓输入，参数化最有效；过滤转义加校验；输出处理是防 XSS，B 选它。


### 13. 隔离装置独有的 SQL 防护规则库在默认配置情况下，可以阻断所有对数据库的管理操作，严格禁止在外网进行数据库的管理维护操作。以下不属于默认配置下禁止的操作有()
- 选项：A.建立、修改、删除用户　B.建立、修改、删除存储过程　C.建立、修改、删除表空间　D.建立、修改、删除配置策略
- 答案：D

### 34. 下列()不是由于 SQL 注入漏洞而造成的危害。

### 36. 事务处理是数据库运行的基本单位。如果一个事务处理成功，则全部数据应更新和提交；如果失败，则已做的全部更新被恢复成原状，好像整个事务处理未进行过一样。这样使数据库保持了一致性。
- 选项：A.正确　B.错误
- 答案：正确
- 🎯答案解析：判 <b>正确（A）</b>。题干关于事务及其原子性、一致性的描述正确。
- 📚知识点讲解：事务（Transaction）是数据库运行的<b>基本单位</b>，四大特性 ACID：<b>A</b>tomicity 原子性（要么全做要么全不做）、<b>C</b>onsistency 一致性（前后数据都合法）、<b>I</b>solation 隔离性（并发事务互不干扰）、<b>D</b>urability 持久性（提交后永久保存）。题干描述的正是原子性（全做/全不做）与一致性。类比：银行转账——扣款和入账要么都成功，要么都回滚，不能只扣不入。
- 💡解题思路：表述符合事务 ACID 特性，判正确。
- 🧠记忆口诀：事务四性 ACID，原子一致隔离持久；要么全做要么全不做，正确判来记牢固。


### 39. 关于“死锁”,下列说法中正确的是()。

- 答案：B
- 🎯答案解析：选 <b>B（只有出现并发操作时，才有可能出现死锁）</b>。
- 📚知识点讲解：死锁四个必要条件：互斥、占有且等待、不可抢占、<b>循环等待</b>。只有在<b>多个事务并发</b>竞争资源时，才可能形成循环等待导致死锁。逐项排除：A 错（竞争相同资源恰恰<b>会</b>死锁）；C 错（禁止并发等于放弃数据库的核心能力，不是可行方法；实际用超时、死锁检测与回滚、约定加锁顺序、一次封锁法）；D 错（数据库系统中同样存在死锁，如两事务互相等待对方持有的锁）。类比：两人各拿一双筷子中的一支，都要等对方放下——这就是并发下的死锁。

- 🧠记忆口诀：死锁必在并发中，循环等待是根因；数据库里也存在，超时检测来破局，B 选并发是答案。

## ③ 索引与约束

- **索引像书的目录**：加速查询，但不是越多越好、也不是每张表必须有。**三道相关题连记**：题 10 选 ABD（错误描述＝每表必须有、能解决安全问题、最多一个索引）；题 47 判错误（每张表必须拥有索引是错的）；题 35 排除 B（多创建索引反而拖慢写入）。
- **约束自动建索引**：Oracle 只为 **PRIMARY KEY（主键）**和 **UNIQUE（唯一）**约束自动建立 **B 树唯一索引**；**CHECK 和外键不会**自动建（题 21 选 BC、题 26 选 ABC，D 项“外键自动建唯一索引”是错的）。实务建议：**外键列要手动建索引**，避免级联删除时全表扫描和锁表。另注意 Oracle 默认行为：**禁用约束会删除对应索引，激活时自动重建**（题 26 的 C 项）。
- **加速索引创建两招**（题 33 选 CE）：**PARALLEL**（并行，多线程一起建）＋ **NOLOGGING**（不写重做日志，减少 I/O）。别选 ONLINE（不提速、反而增加开销）、REVERSE（防热点块）、COMPRESS（省空间但费 CPU）。
- **性能优化**（题 35 选 DE，钉死）：**redo log 放高性能存储**（高频顺序写，放 SSD 显著降低写等待）＋ **临时表空间用 tempfile**（不产生 redo，减少 I/O）。注意：索引不是越多越好（B 错）；A、C 实务中也有优化效果但题库未选，考试以本题库为准。
- **重建索引**（题 8 选 BC，钉死有争议）：改变存储选项、移动索引到其他表空间时需重建；按 Oracle 实际“使用索引监测”不需要重建，本题库答案为 BC，考试以本题库为准。
> ⚠ 核心权衡：索引加速**读**但拖慢**写**。凡见“必须建索引”“索引越多越好”“索引能保安全”都是错误表述。

### 10. 哪些对索引的描述是错误的?()
- 选项：A.每张表必须拥有索引　B.索引可用来解决安全问题　C.索引是用来优化查询表数据的性能的　D.一张表最多只能有一个索引
- 答案：ABD
- 🎯答案解析：选 <b>ABD</b>。错误的描述是：每张表必须拥有索引（A）、索引可用来解决安全问题（B）、一张表最多只能有一个索引（D）。
- 📚知识点讲解：索引的正确认知：①<b>不是每张表必须有索引</b>（A 错，呼应题 47 判断题：小表、频繁更新的表可能不需要索引）；②索引的作用是<b>优化查询性能</b>（C 对），<b>不能解决安全问题</b>（B 错，安全靠权限、加密、审计，不是索引）；③一张表<b>可以建多个索引</b>（D 错，可建主键索引、唯一索引、普通索引、组合索引等）。类比：索引像书的目录——加快查找，但一本书可以有多个目录，也不是每本书都必须要目录（几页的小册子不需要）。
- 💡解题思路：找“错误描述”→ ABD；C 是正确描述不选，选 ABD。
- 🧠记忆口诀：索引不是必须有，也不只一个；它能加速查询但不能保安全；ABD 三项错误记周全。


### 21. Oracle 会为下列哪些约束自动建立索引：
- 选项：A.Check　B.Unique　C.Primarykey　D.Foreignkey
- 答案：BC
- 🎯答案解析：选 <b>BC</b>。Oracle 会为 <b>Unique（唯一）</b>和 <b>Primary key（主键）</b>约束自动建立索引。
- 📚知识点讲解：Oracle 自动建索引的约束：<b>PRIMARY KEY</b>（主键，自动建唯一索引）、<b>UNIQUE</b>（唯一，自动建唯一索引）。<b>不会</b>自动建索引的：<b>CHECK</b>（检查约束，只校验值范围）、<b>FOREIGN KEY</b>（外键，Oracle 不自动建索引；但生产环境建议<b>手动</b>为外键列建索引，避免级联删除时全表扫描和锁表）。呼应题 26。

### 26. 下列关于约束和索引的说法中，正确的是()
- 选项：A.在字段上定义 PRIMARY KEY 约束时会自动创建B树唯一索引　B.在字段上定义 UNIQUE 约束时会自动创建一个B树唯一索引　C.默认情况下，禁用约束会删除对应的索引，而激活约束会自动重建相应的索引　D.定义 FOREIGNKEY 约束时会创建一个B树唯一索引
- 答案：ABC
- 🎯答案解析：选 <b>ABC</b>。正确的是：主键自动创建 B 树唯一索引（A）、唯一约束自动创建 B 树唯一索引（B）、禁用约束会删除索引而激活会重建（C）。
- 📚知识点讲解：呼应题 21：主键（A）与唯一（B）约束都会自动创建 <b>B 树唯一索引</b>；<b>外键不会</b>自动创建唯一索引（D 错）。而 C 描述的是 Oracle 的默认行为：<b>DISABLE 约束会删除对应索引，ENABLE 时自动重建</b>（因为索引是约束的实现基础）。注意：唯一<b>索引</b>不等于唯一<b>约束</b>——索引是物理实现，约束是逻辑规则。
- 💡解题思路：A/B/C 正确，D 错（外键不自动建唯一索引），选 ABC。
- 🧠记忆口诀：主键唯一自动建 B 树唯一索引，禁用删索引启用重建；外键不会自动建唯一索引，ABC 选 D 排除。


### 33. 创建一个新的表索引，使用哪两个选项可以减少所花费的创建时间?
- 选项：A.ONLINE　B.REVERSE　C.PARALLEL　D.COMPRESS　E.NOLOGGING
- 答案：CE
- 🎯答案解析：选 <b>CE</b>。使用 <b>PARALLEL（并行）</b>和 <b>NOLOGGING（不记日志）</b>可以减少索引创建时间。
- 📚知识点讲解：加速索引创建的两个手段：①<b>PARALLEL 并行</b>——多个线程同时扫描表和排序建索引，大幅缩短时间（类比：一个人搬砖 vs 十个人一起搬）；②<b>NOLOGGING 不记重做日志</b>——跳过 redo log 写入，减少 I/O 开销（代价是故障时无法用日志恢复，建完建议备份）。其余选项：<b>ONLINE</b>（在线建索引不阻塞 DML，但会<b>增加</b>开销）、<b>REVERSE</b>（反向键索引，缓解热点块，不提速）、<b>COMPRESS</b>（压缩索引省空间，反而增加 CPU 时间）。
- 💡解题思路：提速两招＝并行 + 不记日志，选 CE。
- 🧠记忆口诀：建索引想快两招灵，PARALLEL 并行加 NOLOGGING；ONLINE 不提速 REVERSE 防热点，CE 选来记分明。

- 选项：A.加大 shared pool size　B.多创建索引　C.使用本地管理表空间　D.redo log 文件单独放到写性能高的存储上　E.临时表空间使用 temporary file

### 47. 每张数据表必须拥有索引。

- 答案：错误
- 🎯答案解析：判 <b>错误（B）</b>。并非每张数据表都必须拥有索引。
- 📚知识点讲解：呼应题 10（“每张表必须拥有索引”是<b>错误描述</b>）。索引的取舍是权衡：索引<b>加速查询</b>但<b>拖慢写入</b>（每次增删改都要同步维护索引）且<b>占用空间</b>。以下情况通常不需要索引：数据量很小的表（全表扫描反而更快）、频繁批量更新的表、很少被查询的表。类比：一本书只有 3 页，不需要目录。
- 💡解题思路：抓“必须”→ 太绝对，判错误。
- 🧠记忆口诀：索引不是必须品，小表和频繁写入的表可以省；有得必有失，说必须就判错误。



## ④ 视图·游标·PL/SQL 对象

- **视图是虚拟表**（只存查询定义，不存数据）：作用是**简化复杂查询**＋**屏蔽敏感数据**（题 16 选 AD）。注意两个“不能”：**不能加速访问**（每次查询都要跑底层 SQL，真加速靠索引或物化视图）、**不能代替基表**。它的另一个价值是提供**多角度观察数据**（题 28 选 D）——同一份数据，销售看联系方式、财务看账期、领导看汇总。呼应题 49：视图支持逻辑独立性。
- **游标四步**：声明 → 打开 → **FETCH 提取** → 关闭。FETCH 时游标**必须已打开**，动作是“**把当前记录加载到已有变量中**”；变量在声明阶段就建好了，不是 FETCH 时才创建（题 11 选 ABD 为“叙述错误”，只有 C 的描述正确）。
- **游标四属性**（题 29 排除 CE）：**%FOUND**（取到了吗）、**%NOTFOUND**（没取到，常用于退出循环）、**%ISOPEN**（打开了吗）、**%ROWCOUNT**（已取几条）。**%ISCLOSE 不存在**（陷阱选项）；**ROWTYPE** 是行类型声明（emp%ROWTYPE）不是游标属性。
- **触发器时机只有两种**（题 17 选 BC）：**Before（之前）**和 **After（之后）**。Trigger 是触发器本身的名字，New 是行级触发器里的伪记录（:NEW 新值、:OLD 旧值），都不是时机。
- **PL/SQL 块能直接跑什么**（题 46 选 BC）：**DML**（INSERT/UPDATE/DELETE/MERGE）和**事务控制**（COMMIT/ROLLBACK/SAVEPOINT）可直接用；**DDL 不能直接跑**（TRUNCATE、ALTER TABLE 必须用动态 SQL：EXECUTE IMMEDIATE）。
- **同义词与命名**：同义词＝对象别名，用途是**简化语句＋隐藏名称和属主＋提供公共访问**（题 32 选 ABC；D“显示名称和所有者”说反了）。表命名四规则（题 41 全选）：同用户不重名、不用保留字、首字符是字母、只能用字母数字下划线（禁空格和单引号）。
> ⚠ 三个“说反了”陷阱：题 32 的 D（隐藏 vs 显示）、题 46 的 DDL（需动态 SQL）、题 29 的 %ISCLOSE（不存在，应是 %ISOPEN）。

### 11. 在 Oracle 中，当 FETCH 语句从游标获得数据时，下面叙述错误的有
- 选项：A.游标打开　B.游标关闭　C.当前记录的数据加载到变量中　D.创建变量保存当前记录的数据
- 答案：ABD
- 🎯答案解析：选 <b>ABD</b>。错误的叙述是：游标打开（A）、游标关闭（B）、创建变量保存当前记录数据（D）。
- 📚知识点讲解：游标使用四步：<b>DECLARE 声明</b>（定义游标和变量）→ <b>OPEN 打开</b>（执行查询）→ <b>FETCH 提取</b>（把当前记录<b>加载到已有变量中</b>）→ <b>CLOSE 关闭</b>。所以 FETCH 执行时：<b>游标必须已是打开状态</b>（A“游标打开”是之前的步骤，不是 FETCH 时发生的动作，故错误）；B“游标关闭”更不是 FETCH 时的事（错误）；C“当前记录的数据加载到变量中”是<b>正确</b>描述（不选）；D“创建变量”发生在 DECLARE 阶段而非 FETCH（错误）。
- 💡解题思路：找“叙述错误”→ A/B/D；C 是 FETCH 的正确行为不选，选 ABD。
- 🧠记忆口诀：游标四步声明打开提取关闭；FETCH 只做加载数据，变量早已声明好；ABD 三项错误找。

### 17. PL/SQL 中，触发器触发的时机有哪两种()

- 答案：BC

- 🧠记忆口诀：触发时机前后分，Before 之前 After 之后；Trigger 是名字 New 是新值，BC 两项才对头。


### 28. 关系数据库系统中，能够为用户提供多种角度观察数据库中数据的机制是()。

### 29. 在 Oracle 中，不属于游标属性的是()

### 32. 同义词有以下()用途
- 选项：A.简化SQL语句　B.隐藏对象的名称和所有者　C.提供对对象的公共访问　D.显示对象的名称和所有者
- 答案：ABC
- 🎯答案解析：选 <b>ABC</b>。同义词的用途：简化 SQL 语句（A）、隐藏对象的名称和所有者（B）、提供对对象的公共访问（C）。

### 41. 表命名时需要遵循的规则中选择正确的是：

### 46. PL/SQL 块中可以使用的下列()命令
- 选项：A.TRUNCATE　B.DELETE　C.SAVEPOINT　D.ALTER TABLE
- 答案：BC
- 🎯答案解析：选 <b>BC</b>。PL/SQL 块中可以直接使用 <b>DELETE</b>（B）和 <b>SAVEPOINT</b>（C）。

## ⑤ SQL 语言与 DML

- **SQL 三分类是本章的分水岭**（必背）：**DDL 数据定义**＝CREATE / ALTER / DROP / TRUNCATE（建改删结构）；**DML 数据操纵**＝**SELECT / INSERT / UPDATE / DELETE / MERGE**（增删改查数据）；**TCL 事务控制**＝**COMMIT / ROLLBACK / SAVEPOINT**。**两道 DML 题对比记**：题 20 选项无 MERGE → 选 **BC**（update、delete）；题 37 选项有 MERGE → 选 **BCD**（MERGE、UPDATE、DELETE）。两次都排除 COMMIT（TCL）和 CREATE（DDL）。
- **聚合函数与日期**（题 18 选 AD）：日期列可用 **MIN/MAX**（日期可比较大小，求最早最晚）和 **COUNT**（统计非空数，任何类型都行）；**不能用 SUM/AVG**（日期求和求平均无意义）；且 **AVG 只接受一个参数**，`avg(start_date, end_date)` 语法本身就是错的。
- **通配符与运算符**（题 45 选 BCD）：LIKE 中 **%** 匹配 0 个或多个字符、**_** 匹配恰好一个字符；**<>** 表示不等于（也可写 !=）。注意 **\*** 在 Oracle 中**不是**通配符——它只用于 `SELECT *`（选所有列），在 LIKE 里就是字面星号（所以 A 错）。
- **ORA-00955 名称冲突**（题 44 选 ABD）：报“名称已被现有对象使用”，即同 schema 下对象名撞车。解决：换名字、**换用户（schema）**、删掉旧对象、给旧对象改名。**改列名没用**——冲突的是表名/对象名不是列名。
- **能连不能建表**（题 30 选 AD）：Oracle 建表需要 **CREATE TABLE** 系统权限。**CONNECT 角色只有 CREATE SESSION**（只能登录），**RESOURCE 角色才含 CREATE TABLE**；只给 create session 也只能登录。注意 C“实例没启动”会导致**连不上**，与“能连接”矛盾，排除。
> ⚠ 题 20 与题 37 是同源题，差异只在选项有无 MERGE——看清选项再选，别背死答案。

### 20. 下列属于 DML 语句的是

### 37. 以下哪些是 DML 语句结构?

- 🎯答案解析：选 <b>BCD</b>。<b>MERGE</b>（B）、<b>UPDATE</b>（C）、<b>DELETE</b>（D）是 DML 语句结构。
- 📚知识点讲解：<b>呼应题 20</b>（那题答案为 BC）：本题选项多了 MERGE，答案为 BCD。<b>MERGE</b> 是 Oracle 的“有则更新、无则插入”（UPSERT）语句，属 DML。排除：A COMMIT 属 TCL（事务控制），E CREATE 属 DDL（数据定义）。三分类记忆表：<b>DDL</b>＝CREATE/ALTER/DROP/TRUNCATE；<b>DML</b>＝SELECT/INSERT/UPDATE/DELETE/MERGE；<b>TCL</b>＝COMMIT/ROLLBACK/SAVEPOINT。
- 💡解题思路：DML＝增删改查 + 合并 → MERGE + UPDATE + DELETE，选 BCD。
- 🧠记忆口诀：MERGE、UPDATE、DELETE 是 DML，COMMIT 管事务 CREATE 管定义；题 20 无 MERGE 选 BC，本题有 MERGE 选 BCD。


### 44. 在 Oracle 生成表时遇到下列错误：ORA-00955-name is already used by existing object。下列哪些选项能纠正这个错误?
- 选项：A.以不同的用户身份生成对象　B.删除现有同名对象　C.改变生成对象中的列名　D.更名现有同名对象
- 答案：ABD
- 🎯答案解析：选 <b>ABD</b>。可以：以不同用户身份生成对象（A）、删除现有同名对象（B）、更名现有同名对象（D）。
- 📚知识点讲解：<b>ORA-00955</b> 错误含义＝“名称已被现有对象使用”，即<b>同一 schema 下对象名重复</b>（表/视图/序列等名字撞车）。解决思路：<b>换个名字</b>、<b>换个用户（schema）</b>（A 对，不同用户下同名是允许的）、<b>删掉旧对象</b>（B 对）、<b>把旧对象改名</b>（D 对）。C 错——改<b>列名</b>没用，报错的是<b>表名/对象名</b>冲突，不是列名冲突。类比：同一小区不能有两栋都叫“1号楼”，但可以换个小区（换用户）、拆掉旧的、或给旧的改名。

- 🧠记忆口诀：ORA-00955 名字撞车，换用户删旧对象或改名旧；改列名没用处，ABD 三项能修复。


### 45. 在 oracle 环境下，以下说法中正确的是：()

## ⑥ Oracle 存储结构与运维

- **表空间是逻辑、数据文件是物理**（题 38 选 AD）：一个表空间**可包含多个**数据文件；一个数据文件**只能属于一个**表空间（不能一对多）。类比：表空间像文件夹（逻辑），数据文件像硬盘上的实际存储块（物理）。
- **扩容三招**（题 42 选 ACD）：数据超过表空间大小时，可**开启自动扩展**、**添加数据文件**、**调大数据文件**。“不能用了就重建表空间”是错误做法（会丢数据且没必要）。
- **bigfile 表空间**（题 14 选 BC）：**只含一个大容量数据文件**＋**段空间自动管理（ASSM）**＋本地管理（非字典管理）。一个数据库可以有多个 bigfile 表空间（A 错）。价值：简化超大型库的数据文件管理。
- **三个网络配置文件别搞混**（题 15 选 D）：**tnsnames.ora**（**客户端**，本地命名＝服务名到主机端口的映射，像手机通讯录）；**listener.ora**（**服务器端**，配监听器）；**sqlnet.ora**（命名方法优先级、超时等参数）。注意 B 选项 “tnsname.ora” **少了个 s**，是拼写陷阱。
- **分区表**（题 23 选 ACD）：一张大表按范围/列表/哈希拆成多个物理分区。可用 ALTER TABLE 拆分分区；每个分区可建**本地索引**（与分区一对一，**维护方便**，是推荐做法）；可只导出单个分区。B 错——全局索引在分区维护时会失效需重建，不是“便于维护”。
- **归档日志**（题 43 选 ABC）：＝在线重做日志写满后的副本。有了它才能在磁盘故障时做**完全恢复**；数据库运行于 **NOARCHIVELOG**（非归档）或 **ARCHIVELOG**（归档）两种模式。D 说反了——ARCHIVELOG 模式下**恰恰就是进行在线日志归档**。类比：在线日志像黑板（写完擦掉重写），归档日志像拍照存档。
- **Oracle 应用两大块**（题 24 选 AC）：**管理**（DBA：安装部署、权限、备份恢复、调优）与**开发**（PL/SQL 编程：表设计、存储过程、触发器）。安装和调试只是这两个方向里的具体环节。
> ⚠ 三个名称陷阱：tnsnames.ora（有 s，客户端）vs listener.ora（服务端）；本地索引（好维护）vs 全局索引（分区动就失效）。
