# 哈希与数字签名

> 零基础通关 · 从数字指纹到可靠签名

## 故事线

怎么证明文件没被改？→ 哈希做「数字指纹」（MD5/SHA-1，定长不可逆）→ RSA 用私钥对指纹「盖章」= 数字签名 → 真实案例 LinkedIn 用不安全 SHA-1 存密码被破，暴露「不安全加密存储」→ 分清边界：网络入侵靠防火墙，内容可信靠签名。

## ① 哈希 / 报文摘要是什么

哈希（Hash）也叫报文摘要或数字指纹。打个比方：你有一篇 10 万字的小说，快递给别人前先自己算一个「指纹」——把全文喂进一台特殊的碎纸机，吐出来一串固定长度的字（比如 128 位）。只要原文改了一个标点，这个指纹就完全变样；但无论原文多长，指纹长度永远不变。
它的三个特点要记牢：① 定长输出（MD5 永远 128 位、SHA-1 永远 160 位）；② 单向（有指纹推不出原文，像碎纸机不能还原）；③ 雪崩效应（改一字符指纹全变）。它不是加密——加密能解密，哈希不能反解。
> ⚠ 易混：MD5 = 128 位、SHA-1 = 160 位，这两个数字要分别钉死，别张冠李戴。

## ② RSA 与数字签名

数字签名解决的是「这东西确实是我发的、且没被改过」。类比：纸质合同上盖章——别人看到章就知道是你签的，且合同内容被改了章就对不上。
计算机里用非对称加密（RSA）来盖章：你用自己的私钥对文件的哈希值加密，这就是「签名」；别人用你的公钥解密，比对哈希，就能验证「确是你签的 + 内容没被改」。
RSA 通常用作数字签名（也用于加密，但题库考的是签名用途）。注意分工：产生摘要/指纹是哈希干的，不是 RSA——RSA 是「盖章」那一步。
可靠的电子签名有四要件（全选）：① 签名制作数据归签名人专有；② 签署时仅由签名人控制；③ 签署后对任意改动能被发现；④ 签署后数据电文内容和形式的改动能被发现。

## ③ 哈希在密码存储中的实战

网站存用户密码，绝不能存明文，也不能用「已被破解的不安全算法」哈希后存。正常做法：用慢哈希 + 加盐（如 bcrypt、scrypt）。
真实案例（LinkedIn，2012）：它用 SHA-1 哈希密码存储，而 SHA-1 已被证明不安全（快、易撞库），结果 650 万条哈希密码泄露，30 多万被破解。这暴露的漏洞是「不安全的加密存储」——不是配置错、也不是传输层没保护，是「存密码的方式本身不安全」。
> ⚠ 考点：看到「用 SHA-1/MD5 这类已被攻破的算法存密码被破解」→ 选「不安全的加密存储」，不是「安全配置错误」也不是「传输层保护不足」。

## ④ 哈希 / 签名的边界与网络防护

哈希和签名是「内容层面」的技术；而「网络边界防御」是另一回事。两者别混。
防火墙：防止外部网侵犯内部网，是在网络边界设的一道墙（选防火墙），不是数字签名、也不是密码认证——签名解决不了「外部入侵」这种网络层问题。
Samba 安全级别（文件共享服务）：提供四种安全级别——share、server、user、domain（全选 ABCD）。这属于服务配置基础，和哈希/签名核心关联弱，了解即可。

- 💡解题思路：💡解题思路：问 RSA 用途，排除 B/C（那是哈希），D 无关，剩 A 数字签名。
- 🧠记忆口诀：🧠记忆口诀：RSA 干啥用？签名它最行；摘要归哈希，莫把活儿混。

**2. 以下算法中属于报文摘要算法的是（ ）。** 

- 选项：A.MD5 / B.EDS / C.RSA / D.AES
- **答案：** A

- 🎯答案解析：🎯答案解析：本题选 A（MD5）。报文摘要算法 = 哈希算法，MD5 是典型代表。
- 📚知识点讲解：📚知识点讲解：报文摘要（哈希）算法把任意长度消息压缩成定长指纹：MD5（128位）、SHA-1（160位）。EDS 不是标准算法；RSA 是非对称加密；AES 是对称加密——三者都不是摘要算法。
- 💡解题思路：💡解题思路：找「哈希/摘要」家族，只有 MD5 是；其余 RSA/AES 是加密、EDS 是干扰项。
- 🧠记忆口诀：🧠记忆口诀：摘要算法 MD5，RSA/AES 靠边站；EDS 凑数莫上当，定长指纹它来算。

**3. 哈希算法 MD5 的摘要长度为（ ）。** 

- 选项：A.64位 / B.128位 / C.256位 / D.512位
- **答案：** B

- 🎯答案解析：🎯答案解析：本题选 B（128 位）。MD5 输出固定 128 位（16 字节）摘要。
- 📚知识点讲解：📚知识点讲解：MD5 无论输入多长，都生成 128 位哈希值。注意和 SHA-1（160位）、SHA-256（256位）区分，别记串。
- 💡解题思路：💡解题思路：MD5 = 128 位是固定考点，直接选 B。
- 🧠记忆口诀：🧠记忆口诀：MD5 摘要一百二八，SHA-1 才是一六零；长度钉死莫混淆，考试常挖这坑。

**5. 什么是可靠的电子签名（ ）。**

**6. LinkedIn 公司发生安全事件，650 万条哈希密码被上传，30 多万密码被破解，原因是使用了哈希算法 SHA1。这暴露了（ ）安全漏洞。**
