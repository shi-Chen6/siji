## 模块1 Web 技术基础（HTML/CSS/ASP）

学 Web 安全前，先懂网页是怎么搭的。HTML 是网页的骨架（标记语言），CSS 是皮肤（样式），ASP 等脚本是大脑（服务端动态生成页面）。

常见 HTML 标记：a 做锚点/链接，table/tr/th/td 画表格（td 是数据单元格、rowspan 跨行、colspan 跨列），表单控件 type 决定长相（submit、button、reset 是按钮，password 是密码框）。

外部样式表用 link 标签引入（不是 style 标签内写，也不是 style 属性行内）。ASP 里 Response.Cookies 是只写的（服务器种、客户端读），Application 对象全局共享、可做网站计数器。

这些基础零件，是后面讲“改页面、偷 Cookie、塞脚本”等攻击的前提——不懂零件，就看不到漏洞在哪。

> 生活类比：网页像一间店面——HTML 是货架和标牌（结构），CSS 是装修（样式），ASP 是后台仓管（动态出数据）。黑客要搞破坏，先得知道货架怎么摆、标牌怎么改。

## 模块2 Cookie 与会话管理安全

Cookie 是网站存在你浏览器里的小纸条，记着“你是谁、登录了没”。三类：Session Cookie（关浏览器即删）、Secure Cookie（只走 HTTPS 防偷看）、HTTP-Only（禁止 JS 读取，防 XSS 偷走）。

注意坑：Cookie 内容可加密（含用户 ID、有效时间），但“加密”不等于“安全”——Secure 是走 HTTPS 不是 HTTP；HTTP-Only 才是防脚本偷。

会话管理要安全：会话数据存/传要加密、登录成功建新会话（防会话固定）、避免 CSRF、合理存活时间超时销毁并清信息。漏洞扫描系统会专门查 Cookie 注入、XSS、Cookie 有效性。

> 生活类比：Cookie 像商场给的会员卡——Session 卡离店作废，Secure 卡只在加密通道递（防被人瞄到），HTTP-Only 卡不让售货员（JS）乱看。卡上信息加密了，但被明文递送照样丢人。

🎯 答案解析：选 C。清除 Cookie 可清除上网痕迹（登录态、浏览偏好等存在 Cookie 里）。

📚 知识点讲解：Cookie 记录登录状态、浏览痕迹；清除它等于“退出并擦掉痕迹”。禁用脚本、禁止 SSL、查看 ActiveX 都不直接清痕迹。

💡 解题思路：问“清除上网痕迹”，Cookie 是痕迹载体，清它最直接；其余三项不相关。

## 模块3 跨站脚本攻击 XSS

XSS（跨站脚本）是攻击者把恶意脚本塞进网页，别的用户一打开就中招。存储型最狠：脏数据存进数据库，所有访客都被执行。

防 XSS 靠三招：输入白名单验证、输出净化（转义）、特殊字符过滤。关键坑：参数化查询防的是 SQL 注入，不是 XSS！

XSS 危害 = 网站挂马、盗各类账号、窃商业资料；它动不了数据库（那是 SQL 注入的活）。

> 生活类比：XSS 像坏人在公共留言板写“看到此条自动转账”的纸条，店员（浏览器）不懂，照念给每个顾客听。存储型是把纸条贴进总台账，人人都中招。

**【自测 24】** 下列（ ）能最好的描述存储型跨站脚本漏洞。

选项：A.不可信任数据通过不可靠的源直接进入 Web 服务器，然后在客户端浏览器显示给用户　B.不可信任数据直接在客户端的 JavaScript 中处理，然后直接在客户端显示　C.不可信任数据包含在动态内容中的数据在没有经过安全检测就存储到数据库中提供给其他用户使用　D.不可信任数据没有任何处理，直接在客户端显示

**答案：** C

🎯 答案解析：选 C。存储型 XSS：不可信数据未经安全检测就“存进数据库”，再发给其他用户显示。

📚 知识点讲解：XSS 三类：反射型（数据进服务器再回显客户端）、存储型（数据存库，别人访问时取出执行）、DOM 型（纯前端 JS）。题干“存储到数据中提供给其他用户”正是存储型。

💡 解题思路：关键词“存储到数据/其他用户使用”=存储型，对应 C；A 偏反射型表述，B/D 不涉存储。

🧠 记忆口诀：存储型 XSS：入库再害人；反射型：即时回显。

## 模块4 跨站请求伪造 CSRF

CSRF（跨站请求伪造）是“借你已登录的身份发请求”：你登录网银没退出，点开坏网页，它就以你权限转账。

会话持续越久，被 CSRF 概率越大；用 POST 只是稍难一点；多步提交也不可靠（可发多个请求模拟）。

防御：重要操作前要求额外信息（验证码/二次确认）、用一次性令牌（token）、限制认证 Cookie 的到期时间。

> 生活类比：CSRF 像有人拿着你忘退的门禁卡，去前台说“帮我转笔钱”——前台认卡不认人。短时效卡 + 每次额外口令（token）就能防。

**【自测 15】** 下列关于跨站请求伪造的说法正确的是（ ）（多选）

选项：A.只要你登陆一个站点 A 且没有退出，则任何页面都可发送一些你有权限执行的请求并执行　B.站点 A 的会话持续的时间越长，受到跨站请求伪造攻击的概率就越大　C.目标站点的功能采用 GET 还是 POST 并不重要，只不过 POST 只是加大了一点点跨站请求伪造的难度而已　D.有时候复杂的表单采用多步提交的方式防止跨站请求伪造攻击其实并不可靠，因为可以发送多个请求来模拟多步提交

📚 知识点讲解：CSRF 是“借你已登录的身份发请求”：你登录 A 没退出，别的页面就能以你权限发请求；会话久则窗口长；POST 只是稍难；多步提交可多发请求模拟。

🧠 记忆口诀：CSRF 借身份：未退可被用、越久越险、POST 稍难、多步可破。

**【自测 17】** 下列措施中，（ ）能帮助减少跨站请求伪造（多选）

## 模块5 SQL 注入与输入验证

SQL 注入是脏数据拼进数据库命令，根因 = 没验证输入。安全编码要对输入做四查：长度、类型、特殊字符、数值范围，且先规范化再验证。

数据库权限按最小化给（应用账号只拿必需权限），降低被注入后的破坏面。

因“未验证输入”引起的漏洞：缓冲区溢出、跨站脚本、SQL 注入（信息泄漏成因更广，不直接对应）。

> 生活类比：输入验证像快递收件安检——量尺寸（长度）、看品类（类型）、查违禁品（特殊字符）、核重量（范围）。不安检，炸弹（注入）就进库。

## 模块6 安全编码与典型漏洞

代码不严谨就出洞：把用户输入直接拼进文件路径（如 reports/ 加 rName 再 delete）会目录遍历，能删任意文件；字符串指针不限制长度会缓冲区溢出。

还有 URL 未授权访问（要按角色明确授权）、不安全加密存储（明文存密码，CSDN 事件）。写代码要校验、最小权限、加密存储。

> 生活类比：路径拼接不校验，像让访客自己填“要删哪个文件”还直接执行——他说“../../机密”就删到根了。最小权限像只给仓库钥匙，不给大门钥匙。

**【自测 26】** 以下代码存在（ ）漏洞。String rName = request.getParameter("reportName");File rFile = new File("/usr/local/apfr/reports/"+rName) ;rFile.delete();

**答案：** D

🎯 答案解析：选 D。代码把用户输入 rName 直接拼进路径并 delete，造成“目录浏览/路径遍历”漏洞（可删任意路径文件）。

📚 知识点讲解：rFile = new File("/.../reports/"+rName) 未校验 rName，攻击者可传 ../../etc/passwd 之类越权访问/删除文件——属目录遍历（路径操纵）。题干选项给“目录浏览”。

💡 解题思路：问漏洞类型，参数拼路径未过滤=目录浏览/路径遍历，非缓冲溢出、SQL 注入、跨站。

🧠 记忆口诀：路径拼接不校验=目录遍历，可越权删文件。

**【自测 27】** 下列代码存在的漏洞是（ ）。 void func(char *str){}

选项：A.文件上传　B.跨站脚本　C.SQL 注入　D.缓存区溢出

## 🃏 速查卡：Web 应用安全 45 题核心

**① Web 基础**：type=password 是密码框；submit/button/reset 是按钮；rowspan 跨行、colspan 跨列；td 是单元格；锚点用 a；外部样式表用 link；Response.Cookies 只写、Application 计数器。

**② Cookie/会话**：Session 退出删、Secure 走 HTTPS、HTTP-Only 防 JS 偷；会话四要：安全存传、登录换、防 CSRF、超时清。

**③ XSS**：存储型入库再害人；防靠输入白名单+输出净化+过滤；参数化查询防 SQL 注入不防 XSS；XSS 害：挂马/盗号/窃密，动不了库。

**④ CSRF**：借登录身份发请求；防御：二次验证+一次性令牌+短 Cookie。

**⑤ 输入验证**：四查（长度/类型/特殊字符/范围）；先规范化再验证；库权限最小化；未验输入→溢出/XSS/SQL 注入。

**⑥ 安全编码**：路径拼接不校验=目录遍历；字符串不限长=缓冲溢出；URL 按角色授权；密码加密存储。

**⑦ 终端/浏览器**：全网必装防病毒；病毒四路：共享/邮件/网页/漏洞；禁脚本不够；新浏览器不等于防黑客；浏览器最低 IE9；Oracle 客户端：SQL*PLUS、PL/SQL Developer。
