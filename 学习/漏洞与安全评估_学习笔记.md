# 漏洞与安全评估 · 零基础系统学习

> 内容来源：题库「漏洞与安全评估（20 题）」｜ 通俗类比 + 考点自测 + 20 题全解析

## 📖 故事线

零基础学漏洞与安全评估，整体地图：系统为什么有漏洞 → 有哪些典型漏洞怎么补 → 怎么扫描发现漏洞 → 怎么检测恶意代码 → 怎么评估整改形成闭环 → 顺带了解它牵连的硬件与布线。6 个模块一路学下来 20 题全拿下。

> 生活类比：漏洞评估像给房子做"安全体检"——先看房子有哪些天生弱点（漏洞基础），再查水管裂缝、门锁隐患（典型漏洞），然后请人挨间敲门试探（扫描检测），再装监控识别坏人手法（恶意检测），最后出整改清单并验收（评估闭环）。


## 模块1 漏洞与脆弱性基础

什么是"漏洞 / 脆弱性"：系统里"可能被攻击者利用的弱点"——代码缺陷、配置错误、管理空子。不是"已发生的攻击"，是"容易被攻击的口子"。

信息安全漏洞表现（Q11）：系统本身"脆"、被非法进入、被各方打、内部人越权提权 → ABCD 全选。

安全漏洞三大来源（Q14）：人（误操作/被钓鱼）+ 技术（代码/配置缺陷）+ 管理（规划策略执行）三方面共同构成。

**【自测 Q11】** 信息安全漏洞主要表现在()

选项：A.系统存在安全方面的脆弱性　B.非法用户得以获得访问权　C.系统易受来自各方面的攻击　D.合法用户未经授权提高访问权限

**答案：** ABCD

**🎯 答案解析**：选 <b>ABCD</b>。信息安全漏洞主要表现为：系统有脆弱性、非法用户获访问权、系统易受各方攻击、合法用户未经授权提权。

**📚 知识点讲解**：漏洞的后果是多方面的：本身“脆”（设计缺陷）、被“钻空子”非法进入、被各方“打”、内部人“越权”提权。四方面全中。

**💡 解题思路**：全选。

**🧠 记忆口诀**：“漏洞四相：脆、进、打、提。”

选项：A.人的因素　B.技术因素　C.规划，策略和执行过程

**答案：** ABC

**🎯 答案解析**：选 <b>ABC</b>。安全“漏洞”从系统整体看包括：人的因素、技术因素、规划/策略/执行过程。

**📚 知识点讲解**：漏洞不只是“技术 bug”：人（员工误操作/被钓鱼）、技术（代码/配置缺陷）、管理（规划策略执行不到位）三方面共同构成。三者都选。

**💡 解题思路**：全选 ABC。

**🧠 记忆口诀**：“漏洞三方面：人、技、管。”

## 模块2 典型漏洞与补丁

缓冲区溢出（Q1）：程序没检查输入长度，往固定缓冲区写超量数据覆盖相邻内存，黑客植入恶意代码。根因是代码缺陷，最可靠解法是装最新补丁（非防火墙/IDS/杀毒）。

Unicode 漏洞（Q13）：利用扩展字符绕过敏感路径、借 cmd.exe 执行命令。限制 cmd 访问/调用权限可防。

Apache 安全配置（Q5）："显示版本号"不安全（暴露已知漏洞），应装补丁、只启必需模块、用低权用户/组运行。

**【自测 Q1】** 许多黑客攻击都是利用软件实现中的缓冲区溢出的漏洞，对于这一威胁，最可靠的解决方案是()。

选项：A.安装防火墙　B.安装入侵检测系统　C.给系统安装最新的补丁　D.安装防病毒软件

**答案：** C

**🎯 答案解析**：选 <b>C</b>。最可靠方案是“给系统安装最新的补丁”，从源头修补溢出漏洞。

**📚 知识点讲解**：缓冲区溢出是程序未检查输入长度、往固定大小缓冲区写了超量数据，覆盖相邻内存、被黑客植入恶意代码。补丁修复的是“程序本身的缺陷”，所以打补丁治本。

**💡 解题思路**：防火墙/IDS/杀毒都治标不治本：防火墙拦不了已授权正常端口上的溢出利用；IDS 只报警不阻断；杀毒靠特征库，对零day溢出无能为力。只有补丁从代码层面堵洞。

**🧠 记忆口诀**：“溢出漏洞补丁堵，防火墙IDS只是护。”

**【自测 Q13】** 限制网络用户访问和调用cmd的权限可以防范Unicode 漏洞。()

选项：A.正确　B.错误

**答案：** 正确

**🎯 答案解析**：正确。限制网络用户访问和调用 cmd 的权限，可防范 Unicode 漏洞利用。

**📚 知识点讲解**：Unicode 漏洞（经典 IIS 漏洞）利用扩展字符绕过敏感路径、借 cmd.exe 执行系统命令。收紧对 cmd 的访问/调用权限，攻击者就拿不到命令行，漏洞利用被阻断。所以限制 cmd 权限是有效防范措施。

**💡 解题思路**：题干对。

**🧠 记忆口诀**：“Unicode 借 cmd 跑，权限收紧跑不了。”

**【自测 Q5】** 下列选项中，()不是Apache 服务器的安全配置事项。

选项：A.确保已经安装了最新的安全补丁　B.只启动应用程序需要的服务模块　C.显示Apache 的版本号　D.确保Apache 运行在正确的用户和组下

**答案：** C

**🎯 答案解析**：选 <b>C</b>。Apache 安全配置里“显示版本号”反而是不安全的，不应做。

**💡 解题思路**：找“不是安全配置”：A/B/D 都更安全，C 暴露版本=更危险。

**🧠 记忆口诀**：“版本号别显，暴露挨打先。”

## 模块3 漏洞扫描与检测

脆弱性分析 = 漏洞扫描（Q12）：自动检测远程/本地系统安全弱点，两者一回事。

端口扫描（Q4）：像"敲门"探哪些端口有回应，判断能否远程登录（如 22/3389）。

完整扫描不含（Q17）："发现漏洞后能不能解决"是整改环节，不属于扫描本身。

终端防护（Q7）：防病毒/补丁管理/漏洞扫描直接护终端；防止非法外联管数据不出网，不直接护终端。

**【自测 Q12】** 脆弱性分析技术，也被通俗地称为漏洞扫描技术。该技术是检测远程或本地系统安全脆弱性的一种安全技术。

选项：A.正确　B.错误

**答案：** 正确

**🎯 答案解析**：正确。脆弱性分析技术通俗就叫“漏洞扫描技术”，检测远程或本地系统的安全弱点。

**📚 知识点讲解**：脆弱性（vulnerability）=系统可能被攻破的弱点；漏洞扫描就是自动化的脆弱性分析——扫系统配置/补丁/开放端口找弱点。两者是一回事的不同说法。

**💡 解题思路**：题干说“也被通俗称为”——对。

**🧠 记忆口诀**：“脆弱性分析=漏洞扫描，换汤不换药。”

---

**【自测 Q4】** 预知某主机是否可远程登录，可利用()进行检测。

选项：A.端口扫描　B.病毒查杀　C.包过滤　D.身份认证

**答案：** A

**🎯 答案解析**：选 <b>A</b>。预知某主机能否被远程登录，用“端口扫描”探它是否开放了远程登录端口（如 22/3389）。

**📚 知识点讲解**：端口扫描像“敲门”：发探测包看哪些端口有回应，从而判断服务开着没、能否登录。病毒查杀看文件、包过滤是防火墙动作、身份认证是登录环节不是探测手段。

**💡 解题思路**：“预知能否登录”=先探端口→选 A。

**🧠 记忆口诀**：“想知能不能登，端口扫描先敲门。”

**【自测 Q17】** 一次完整的网络安全扫描不包括以下哪个阶段()。

选项：A.根据检测到的漏洞看能否解决　B.发现目标后进一步搜集目标信息　C.根据搜集到的信息判断或者进一步测试系统是否存在安　D.发现目标主机或网络

**答案：** A

**🎯 答案解析**：选 <b>A</b>。一次完整网络安全扫描“不包括”“根据检测到的漏洞看能否解决”。

**📚 知识点讲解**：完整扫描流程：发现目标→搜集目标信息→判断/测试是否存在漏洞。至于“发现漏洞后能不能解决”是整改环节，不属于“扫描”本身。所以 A 是扫描不包含的步骤。

**💡 解题思路**：找“不包括”→ A。

**🧠 记忆口诀**：“扫描只管找洞，解决是后话。”

**【自测 Q7】** ()技术不能保护终端的安全。

选项：A.防病毒　B.补丁管理　C.防止非法外联　D.漏洞扫描

**答案：** C

**🎯 答案解析**：选 <b>C</b>。“防止非法外联”保护的是“数据不出网”，不能直接保护终端本机安全。

**📚 知识点讲解**：终端安全防护手段：防病毒（杀毒）、补丁管理（修漏洞）、漏洞扫描（查弱点）都直接护终端。而“防止非法外联”是管“内网机器偷偷连外网”，属边界/数据防泄露，不直接加固终端自身。

**💡 解题思路**：找“不能保护终端”：A/B/D 直接护终端，C 是外联管控。

**🧠 记忆口诀**：“外联管控防泄露，终端加固靠杀补扫。”

## 模块4 恶意代码检测手段

扫描法（Q16）：用病毒特征字符串比对文件，命中即中毒（特征代码/特征字扫描法）。

特征码/行为检测风险（Q18）：都要"跑"可疑代码才能提取特征或观察行为，有安全风险。

定量 vs 定性（Q15）：定量精确但参数难量化；实际多用定性或结合。

**【自测 Q16】** ()是用每一种病毒体含有的特征字符串对被检测的对象进行扫描，扫描法包括特征代码扫描法和特征字扫描法。

选项：A.行为检测法　B.扫描法　C.校验和法　D.比较法

**答案：** B

**🎯 答案解析**：选 <b>B</b>。用病毒体特征字符串扫描被检对象的，是“扫描法”（含特征代码扫描法、特征字扫描法）。

**📚 知识点讲解**：扫描法=拿已知病毒的特征串（一段独特字节）去比对文件，命中即中毒。行为检测法看行为、校验和法看文件哈希变化、比较法看前后差异，都不靠“特征字符串扫描”。

**💡 解题思路**：找“特征字符串扫描”→ 扫描法 B。

**🧠 记忆口诀**：“病毒特征串比对，扫描法最对。”

---

**【自测 Q18】** 基于特征码的扫描技术和基于行为的检测技术都需要执行潜在的恶意代码并分析它们的特征或行为，但是这可能会给系统带来安全问题。

选项：A.正确　B.错误

**答案：** 正确

**🎯 答案解析**：正确。基于特征码和基于行为的检测技术都需执行潜在恶意代码并分析其特征/行为，这本身可能给系统带来安全风险。

**📚 知识点讲解**：这两类检测要在沙箱/监控环境里“跑”可疑代码才能提取特征或观察行为；一旦逃逸或误判，运行恶意代码就有风险。所以题干说“可能带来安全问题”是对的。

**💡 解题思路**：题干对。

**🧠 记忆口诀**：“特征行为都要跑，跑了就有险。”

---

**【自测 Q15】** 虽然在安全评估过程中采取定量评估能获得准确的分析结果，但是由于参数确定较为困难，往往实际评估多采取定性评估，或者定性和定量评估相结合的方法。

选项：A.正确　B.错误

**答案：** 正确

**🎯 答案解析**：正确。定量评估虽准但参数难定，实际多用定性评估或定性与定量结合。

**📚 知识点讲解**：安全评估：定量=用数字打分（如风险值），精确但参数（资产值/发生概率）难量化；定性=高/中/低分级，易操作。所以实践以定性为主或结合。题干表述正确。

**💡 解题思路**：题干对。

**🧠 记忆口诀**：“定量虽准参数难，定性定性最常用。”

## 模块5 安全评估闭环与整改

漏洞挖掘及修复（Q10）贯穿四阶段：开发→测试→上线→运行。著作权管理/第三方测试/安全加固都不覆盖四阶段。

南网基线整改交付物（Q8）：漏洞扫描器渗透测试结果 + 第三方人工渗透测试结果（工具+人工，避自查盲区）。

**【自测 Q10】** 下列安全活动中，()涉及信息系统开发、测试、上线、运行四个阶段。

选项：A.软件著作权管理　B.第三方安全测试　C.安全加固　D.漏洞挖掘及修复

**答案：** D

**🎯 答案解析**：选 <b>D</b>。“漏洞挖掘及修复”贯穿信息系统开发、测试、上线、运行四个阶段。

**📚 知识点讲解**：漏洞不是上线才有的，开发阶段写代码就可能引入、测试阶段挖、上线后运维持续修、运行阶段监控。所以“漏洞挖掘及修复”覆盖全生命周期四阶段。软件著作权管理是法律、第三方安全测试只是测试环节、安全加固是上线后动作，都不覆盖四阶段。

**💡 解题思路**：找“涉及四个阶段”→ 漏洞挖掘及修复。

**🧠 记忆口诀**：“漏洞挖修贯四段，生老病死都管。”

## 模块6 延伸：硬件接口与综合布线

印刷图片录入设备（Q3）：需采集设备（扫描仪/数码相机/数字摄像机）；投影仪是输出设备，不能录入。

IDE 设备（Q6）：硬盘、CD-ROM 驱动器、刻录机走 IDE；扫描仪不走。

管槽安装（Q9）：路由与建筑基线一致、注意布置、横平竖直弹线定位；"走最短路由"非基本要求。

**【自测 Q3】** 以下设备中，不能使用()将印刷图片资料录入计算机。 🟣 *（了解即可）*

选项：A.扫描仪　B.投影仪　C.数字摄像机　D.数码相机

**答案：** B

**🎯 答案解析**：选 <b>B</b>。投影仪不能把印刷图片“录入”计算机；扫描仪、数字摄像机、数码相机都能。

**📚 知识点讲解**：印刷图片是纸质的，要变成电脑里的数字图像需“采集/输入”设备。扫描仪扫平面稿；数码相机/数字摄像机拍实物；投影仪是“输出”设备，把电脑画面放大投到屏幕，方向相反。

**💡 解题思路**：找“不能录入”：A/C/D 都是输入采集类，B 投影仪是放映输出。

**🧠 记忆口诀**：“录入靠采不靠投，投影只管往外秀。”
