# 模块一 Linux/Unix 基础概念

## 1.1 操作系统 = 内核(Kernel)+ 壳(Shell)

**大白话解释**:Linux/Unix 操作系统在概念上分两部分:
- **内核(Kernel)**:系统的"发动机/大脑",负责**处理器管理、存储管理、文件管理、设备管理**,还实现**同步、进程间通信、信息传递**等底层操作;
- **壳(Shell)**:用户与内核之间的"翻译官/界面",接收你敲的命令,转给内核执行。

> 🎯 **类比**:内核像**厨房后厨**(做饭:管火、管菜、管锅),Shell 像**前台服务员**(接单、传话)。你(顾客)通过服务员(Shell)点菜,后厨(内核)才能真正做出菜来。

> ⚠️ **常见错误说法**:"壳(Shell)实现同步、进程间通信、信息传递"——**错!** 这些底层操作是**内核(Kernel)** 的功能,Shell 只负责解释命令、搭桥。

## 1.2 文件系统结构:树型

**大白话解释**:UNIX/Linux 的文件系统是**树型结构**——像一棵倒着长的树,**根是 "/"**,树枝是目录,树叶是文件。从根出发,一层层展开。

> 🎯 **类比**:Linux 文件系统像**一棵大树**(根 /),Windows 像**一排平房**(C:、D: 各自独立)。树的任意一个"树枝"(目录)都能挂"树叶"(文件)。

> 💡 **例子**:路径 `/etc/passwd` 就是从根(/)出发,进入 etc 目录,找到 passwd 文件——"顺着树枝找到树叶"。

<details><summary>📖 点击查看答案与解析</summary>

**详细解析**:

**结论**:选 **B**。记忆锚点:**"Linux 文件系统 = 一棵大树"**。
</details>

## 1.4 用户与 UID:数字身份

**大白话解释**:Linux 里每个用户都有一个**数字 ID(UID)** 和**组 ID(GID)**——系统内部用数字"认人",不用名字。

**用户分类(传统 UNIX 划分)**:
- **超级用户(root)**:UID = 0,最高权限;
- **普通用户**:UID/GID 在 **500~60000** 之间,只能进行普通操作;
- **伪用户(系统账户)**:UID 较小(如 1~499),用于运行系统服务,不能登录。

> 🎯 **类比**:UID 像**员工工号**——系统认"工号"不认"名字"。root 是"工号 0 号的老板",普通用户是"工号 500 号之后的普通员工",伪用户是"机器人账号"(专门跑程序,不坐班)。

> ⚠️ **传统 UNIX 规定**:用户名**最多 8 个字符**,内部表示为一个 **16 位的数字(UID)**。(现代 Linux 用户名可更长,但考试按传统表述。)

2. 伪用户 UID 较小(1~499 等),超级用户(root)UID = 0。

</details>

## 1.5 命名管道(FIFO)

**大白话解释**:**管道(Pipe)** 是进程间通信的方式,把一个命令的输出"接"给另一个命令当输入。管道分两种:
- **无名管道**:只在有亲缘关系的进程间用,临时存在;
- **命名管道(FIFO)**:有名字的管道文件,无亲缘关系的进程也能通过它通信。

**考点**:FIFO 通常被称为 **命名管道(有名管道)**。

> 🎯 **类比**:无名管道像**两个人面对面传纸条**(临时、直接);命名管道像**小区里的公共信箱(FIFO)**——任何人都可以往信箱投信、取信,信箱一直在那(有名字的文件)。

### ✏️ 真题演练 7(题库 #40)

**【单选】在 Linux 系统中,____ 通常称为 FIFO。**
A. 无名管道　　B. 有名管道　　C. 文件管道　　D. 命名管道

<details><summary>📖 点击查看答案与解析</summary>

**答案:D**

**详细解析**:
1. **FIFO(First In First Out,先进先出)= 命名管道**——一种有名字的管道文件。
2. 选项 B"有名管道"与 D"命名管道"同义,本题答案取 **D**。

**结论**:选 **D**。记忆锚点:**"FIFO = 命名管道(公共信箱)"**。
</details>

# 模块二 账户与系统配置安全

## 2.1 账号文件保护:守住"户口本"

**大白话解释**:Linux 的用户信息存在两个核心文件里:
- **/etc/passwd**:用户账户"户口本"(用户名、UID、主目录等);
- **/etc/group**:用户组"户口本"(组名、GID、组成员)。

**保障账号安全最为关键的措施**:让 **/etc/passwd 和 /etc/group 必须有写保护**(普通用户不能改)——否则攻击者直接往"户口本"里加一个"自己人"账户,系统就沦陷了。

> 🎯 **类比**:这两个文件像**小区的住户登记簿**——如果登记簿谁都能改,坏人可以直接把自己"登记成业主",门禁(权限)就形同虚设。所以**登记簿必须锁起来(写保护)**。

> 💡 **延伸**:真实系统中密码常以密文存在 **/etc/shadow**(影子文件,更安全),passwd 中只有占位符。

### ✏️ 真题演练 8(题库 #1)

**【单选】保障 UNIX/Linux 系统帐号安全最为关键的措施是 ____。**

B. 删除 /etc/passwd、/etc/group
C. 设置足够强度的帐号密码
D. 使用 shadow 密码

<details><summary>📖 点击查看答案与解析</summary>

**答案:A**

**详细解析**:
1. **A 对(本题答案)**:账号文件(/etc/passwd、/etc/group)**写保护**是保障账号安全的**最根本措施**——防止攻击者篡改账号文件、添加非法账户。
2. B 错:删除这两个文件系统直接瘫痪,荒唐;
3. C 错:强密码虽重要,但不是"账号文件层面"的关键防护;
4. D 错:shadow 密码是加强措施,但不是题目说的"最为关键"。

**结论**:选 **A**。记忆锚点:**"户口本锁起来,账号才安全"**。
</details>

## 2.2 Shell 启动文件:登录时自动执行的"开机自启"

**大白话解释**:Shell 启动时,会自动执行**用户主目录(~)下**的配置文件,用来设置别名、环境变量等。不同 Shell 的启动文件不同:
- **csh(一种 Shell)**:启动时自动执行 `~/.cshrc`;
- bash:执行 `~/.bashrc`、`~/.bash_profile`;
- 退出时执行 `~/.logout`。

> 🎯 **类比**:Shell 启动文件像**手机的开机自启应用**——一开机(打开 Shell)就自动运行里面的命令,帮你把"环境"准备好。

## 2.3 运行级别:系统"工作模式"

**大白话解释**:**运行级别(Runlevel)** 是 Linux 的"工作模式"编号,数字不同,系统的状态不同(旧式 SysV 风格):

| 运行级别 | 含义 |
|---------|------|
| 0 | 关机 |
| 1 | 单用户模式(维护模式) |
| 3 | **多用户字符界面模式**(命令行) |
| 5 | **多用户图形界面模式**(有桌面) |
| 6 | 重启 |

**考点**:
- 图形界面的多用户模式 = **运行级别 5**;
- 查看系统默认运行级别:查看 **/etc/inittab** 文件。

> 🎯 **类比**:运行级别像**手机的电量/模式**——3 是"省电文本模式"(纯命令行),5 是"全功能模式"(图形桌面)。想知道手机默认用什么模式,看"设置"(/etc/inittab)。

# 模块三 目录结构与配置文件

## 3.1 Linux 三大目录:/etc、/proc、/dev

**大白话解释**:Linux 目录树里,有几个目录必须记住(考试最爱考):

| 目录 | 存放内容 | 一句话记忆 |
|------|---------|-----------|
| **/etc** | **操作系统的配置文件** | 配置文件之家 |
| **/proc** | **进程和系统信息**(虚拟文件系统) | 实时镜子 |
| **/dev** | **设备文件** | 设备登记处 |

- **/etc**:所有服务的配置文件都在这,如 /etc/passwd、/etc/dhcpd.conf;
- **/proc**:虚拟文件系统,存放进程与系统运行信息(不占磁盘);
- **/dev**:设备文件,如 /dev/sda(硬盘)、/dev/cdrom(光驱)。

> 🎯 **类比**:/etc 像**物业办公室**(所有规章制度/配置文件都在这);/proc 像**实时监控屏**(系统当前状态一目了然);/dev 像**设备仓库**(每个硬件都有一个"代表"文件在这)。

## 5.1 Linux 的安全性目标

## 5.2 溢出攻击:栈上的"阴谋"

**大白话解释**:**溢出攻击(Buffer Overflow)** 是经典攻击手法:程序在内存里开了一块固定大小的"缓冲区",攻击者塞入超量数据,把**紧邻的堆栈区域**也覆盖掉——其中最关键的是**修改堆栈记录中进程的返回地址**。

**溢出攻击的核心**:修改堆栈记录中**进程的返回地址**,让程序"返回"到攻击者指定的恶意代码处执行。

> 🎯 **类比**:程序执行就像**按剧本演戏**,演到"返回"环节会照着**备忘录(返回地址)** 去下一幕。攻击者往道具箱(缓冲区)里塞太多东西,把"备忘录"上写的"下一幕地点"改成了"陷阱地点"——程序一返回就走进了陷阱(恶意代码)。

### ✏️ 真题演练 29(题库 #12)

## 5.3 文件访问一致性:加锁策略

**大白话解释**:当**多个进程/线程同时访问同一个文件**时,可能出现"你写我删、互相打架"导致数据不一致。解决办法:**加锁策略(Lock)**——同一时刻只允许一个进程"独占"写文件,其他进程排队等。

> 🎯 **类比**:加锁像**图书馆的洗手间**——一次只能进一个人,其他人门口排队,避免"里面有人还硬闯"的混乱。

### ✏️ 真题演练 30(题库 #13)

**【单选】当多个进程或线程对同一文件进行访问时,应采取 ____ 措施保证文件数据在访问过程中的一致性。**
A. 加锁策略　　B. 互相竞争　　C. 不需要采取任何措施　　D. 共同访问

<details><summary>📖 点击查看答案与解析</summary>

**答案:A**

**详细解析**:
1. 多进程/线程并发访问同一文件,要用**加锁(Lock)** 保证一致性。
2. 干扰项:互相竞争/共同访问恰恰会造成混乱,不采取措施更不行。

**结论**:选 **A**。记忆锚点:**"并发访问同一文件 = 加锁排队"**。
</details>

## 5.4 后门程序:悄悄留下的"密道"

**大白话解释**:**后门程序(Backdoor)** 是攻击者入侵后悄悄留下的"秘密通道",方便以后随时再进来。

**后门程序通常具有的功能**:
- **远程桌面**、**远程终端**(远程操控);
- **远程进程表管理**(查看/控制进程)。

**后门程序通常不具有的功能**:**远程开机**——电脑都关机/断电了,后门程序也没法运行,自然做不到"远程开机"(那要靠网络唤醒 Wake-on-LAN 等硬件功能)。

> 🎯 **类比**:后门像**小偷在房子后墙挖的暗门**——能远程开锁(远程终端)、能看屋里情况(进程管理),但"人在外面把整栋楼断电了(关机)"就进不去了,谈不上"远程开机"。

### ✏️ 真题演练 31(题库 #3)

A. 远程桌面　　B. 远程终端　　C. 远程进程表管理　　D. 远程开机

<details><summary>📖 点击查看答案与解析</summary>

**答案:D**

**详细解析**:
1. 后门常有功能:**远程桌面、远程终端、远程进程管理**(都是"进来之后"能做的事)。
2. **远程开机(D)不是后门的功能**——关机状态下后门无法运行,远程开机需依赖硬件唤醒技术。
3. 找"不具有" → 选 **D**。

**结论**:选 **D**。记忆锚点:**"后门管'进来后',管不了'开机前'"**。
</details>

## 5.5 安全配置:加固的"注意事项"

**大白话解释**:系统安全配置有两个常见话题:

**① 配置管理应注意**:
- **使用最少特权进程和服务账户**(权限最小化);
- **确保配置存储的安全**;
- **单独分配管理特权**(特权分离);
- (❌"准许应用程序调用底层系统资源"是**错误**做法,安全上要禁止/限制)。

**② 常见的安全配置错误**:
- **网站没有禁止目录浏览功能**(暴露文件目录);
- **服务器没有及时打安全补丁**;
- (❌"没有对系统输出数据处理""没有对用户输入数据验证"属于**Web 开发**问题,不算"安全配置错误"范畴)。

> 🎯 **类比**:安全配置像**给机房做安保方案**——给每个岗位只发"够用"的钥匙(最少特权)、钥匙分开保管(特权分离)、机房图纸锁起来(配置存储安全);最常见的错误是"大门钥匙没换(没打补丁)"和"窗户不拉帘(目录可浏览)"。

## 5.6 日志安全存储

**大白话解释**:业务日志要**安全存储与访问**,正确做法:
1. **对日志记录进行数字签名**,实现防篡改;
2. **日志保存期限与系统应用等级相匹配**(重要系统日志留更久);
3. **日志采用只读方式归档保存**;
4. (❌把日志**保存到 WEB 目录下**是**错误**做法——等于把日志公开到网上!)

> 🎯 **类比**:日志像**案发现场的监控录像**——要**签名封存**(数字签名防篡改)、**按案件重要性保留**不同年限(期限匹配)、**只读归档**(不能随便改);把录像传到"广场大屏幕"(WEB 目录)上显然是错误。

<details><summary>📖 点击查看答案与解析</summary>

**答案:BCD**

**详细解析**:
1. **B 对**:数字签名防篡改;
2. **C 对**:保存期限与应用等级匹配(重要系统留更久);
3. **D 对**:只读方式归档保存;
4. **A 不选(反向陷阱)**:把日志放 WEB 目录等于**公开暴露日志**,是错误做法。

**结论**:选 **BCD**。记忆锚点:**"日志:签名、按级留、只读存;绝不挂网上"**。
</details>

## 5.7 SELinux:安全强化模块

**大白话解释**:**SELinux(Security-Enhanced Linux)** 是 Linux 的**强制访问控制**安全模块,给进程和文件都贴上"安全标签"。

**SELinux 标签中有几个字段**:类型(Type)、用户(User)、角色(Role)、层次(Level)等。
- **"用户"字段**:记录了**用户登录后所属的 SELinux 身份**。

> 🎯 **类比**:SELinux 像**机场的安检分级**——每个人(进程)都有"证件"(安全标签),证件上写清"身份(用户)、职务(角色)、类型(类型)";"你以什么身份进来的"就记录在**用户字段**里。

### ✏️ 真题演练 35(题库 #43)

**【单选】____ 字段记录了用户登录后所属的 SELinux 身份。**
A. 类型　　B. 用户　　C. 层次　　D. 角色

<details><summary>📖 点击查看答案与解析</summary>

**答案:B**

**详细解析**:
1. SELinux 上下文中,记录"用户登录后的 SELinux 身份"的是**用户(User)字段**。
2. 干扰项:类型(Type)管文件/进程类型、角色(Role)管角色、层次(Level)管安全级别。

**结论**:选 **B**。记忆锚点:**"SELinux 身份看'用户'字段"**。
</details>

# ⚠️ 常见误区警示

1. **Shell 不等于内核**:同步、进程间通信是**内核**的功能,Shell 只是解释命令(S34 考点)。
2. **umount 少个 n**:Linux 卸载命令是 **umount**,不是 unmount(S20 考点)。
3. **cp -f 是强制覆盖,cp -i 才是询问不覆盖**:-f 恰恰会"不问直接盖"(S6 考点)。
4. **后门没有"远程开机"功能**:关机状态下后门跑不起来(S3 考点)。
5. **日志不能放 WEB 目录**:那是把日志公开暴露(S21 考点)。
6. **SQL Server 是数据库,不是操作系统**(S19 考点)。
7. **"准许应用程序调用底层系统资源"是安全配置错误**:安全上要限制,不是准许(S15 考点)。
8. **"没验证输入/输出"属于开发问题,不算"安全配置错误"**(S18 考点)。
9. **grep 人人可用,不限 root**(S27 考点)。
10. **图形界面 = 运行级别 5,不是 3**:3 是字符界面(S24 考点)。
