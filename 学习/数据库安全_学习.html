故事线（先看这里，能省一半力气）：本章 61 题名为“数据库安全”，实际分三层——真正的安全题约 10 题（模块②的 SQL 注入三考法、隔离装置、配置存储、默认密码，以及模块①的授权与加密）；Oracle DBA 运维题约 30 题（索引、约束、视图、游标、PL/SQL、表空间、分区、归档日志）；完全跑题的灌水题 14 题（Word/Excel/HTML/编译符号表/编码风格/媒体分类，全在模块⑦）。学习顺序：先打地基（关系模型、字段是最小的运算与加密单位、两级数据独立性、安全三支柱）→ 再攻安全核心（注入怎么防/危害是什么/类型检查能防，事务 ACID 与死锁）→ 再学性能优化的主角索引与约束 → 然后是与开发最贴近的视图、游标、PL/SQL → 接着是 DML 三分类与日期函数、通配符 → 最后是 Oracle 存储结构与运维三配置文件 → 偏题区刷一遍记结论即可。一张速查卡钉死所有易混点。

① 数据库基础概念与安全模型

关系模型是地基：关系模型＝二维表，表与表之间靠公共属性（外键）联系（题 19）。类比：两张 Excel 表用"学号"这一列关联。对比：层次模型＝树形（组织架构）、网状模型＝图形（指针链接）。SQL Server、Oracle、MySQL 都是典型的关系型数据库产品（题 48 判正确）。

"字段"是本章两个"最小"的答案（配对记忆）：关系运算的最小单位是字段（题 50，因为投影操作就是选列）；加密的最小单位也是字段（题 51，只加密身份证号、密码等敏感列）。层次顺序：数据库 > 表 > 记录（行） > 字段（列）。

数据独立性分两级：物理独立性＝内模式（存储结构）变，模式不变；逻辑独立性＝模式变，用户程序不变（题 7 选 D）。而视图正是实现逻辑独立性的核心手段，所以说"视图不支持逻辑独立性"是错的（题 49 判错误）。

数据库安全三支柱：①授权粒度——数据对象范围越小（粒度越细）授权越灵活，但系统开销越大（题 12 选 B）；②静态授权＝隐性授权——用户对自己拥有的数据自动有全权，无需显式授权（题 52 判正确）；③权限分配用权限校验矩阵表示——行是用户、列是对象、格子里写权限（题 54 选 B）。

安全措施边界：安全措施＝用户标识与鉴别、存取控制、视图、审计、数据加密；并发控制属于事务管理，不是安全措施（题 40 选 D）。加密特点：数据库加密不能简单采用对称密钥（需多级/混合密钥体制），且库名/表名/记录名/字段名应各有子密钥（题 53 选 C 为"描述错误"）。

⚠ 配对记忆：题 50 与题 51 答案都是"字段"；题 7 逻辑独立 vs 物理独立看"变的是模式还是存储"。

② 事务并发与 SQL 注入防护（本章安全核心）

SQL 注入三考法（本章最重要考点）：①怎么防——参数化查询（最有效，让 SQL 结构与数据分离）、输入过滤、输入有效性检查；而"对用户输出进行处理"防的是 XSS 不是注入（题 6 选 B）；②危害有哪些——看改删数据、访问系统表、提权到 DBA；而"控制受害者机器攻击其他网站"是僵尸网络的危害不是注入（题 34 选 D）；③类型检查能防吗——能！固定类型的字段（如纯数字 ID）强制校验类型，注入 payload 带的引号直接被挡（题 55 判正确）。

隔离装置的 SQL 防护：默认严格模式阻断对数据库的一切管理操作——建删用户、建删存储过程、建删表空间都禁；而"配置策略"是隔离装置自身的配置，不在禁止之列（题 13 选 D）。呼应"网络攻击类型"章题 21（逻辑强隔离四功能）。

配置存储安全四要求（题 27 全选）：放对地方（别放 Web 目录）、不明文存储、加密 + 访问控制、变更要授权且留痕。类比：保险柜放内室、钥匙不挂门上、只有经理能开、每次开都登记。

默认密码必须改（题 61）：Oracle 四大默认账号——sys / change_on_install（最高权限）、system / manager、scott / tiger、aqadm / aqadm。记忆妙招：sys 的密码字面意思就是"安装后请改掉"。

事务与死锁：事务是数据库运行的基本单位，ACID 四性——原子性（要么全做要么全不做）、一致性、隔离性、持久性（题 36 判正确）。死锁只在并发时才可能出现（题 39 选 B）——多事务竞争资源形成循环等待；解决靠超时、死锁检测回滚、约定加锁顺序，而不是禁止并发。

⚠ 三处"找不同"：题 6 找"不能防"（输出处理）、题 34 找"不是危害"（控制机器）、题 40 找"不是安全措施"（并发控制）。

③ 索引与约束

索引像书的目录：加速查询，但不是越多越好、也不是每张表必须有。三道相关题连记：题 10 选 ABD（错误描述＝每表必须有、能解决安全问题、最多一个索引）；题 47 判错误（每张表必须拥有索引是错的）；题 35 排除 B（多创建索引反而拖慢写入）。

约束自动建索引：Oracle 只为 PRIMARY KEY（主键）和 UNIQUE（唯一）约束自动建立 B 树唯一索引；CHECK 和外键不会自动建（题 21 选 BC、题 26 选 ABC，D 项"外键自动建唯一索引"是错的）。实务建议：外键列要手动建索引，避免级联删除时全表扫描和锁表。另注意 Oracle 默认行为：禁用约束会删除对应索引，激活时自动重建（题 26 的 C 项）。

加速索引创建两招（题 33 选 CE）：PARALLEL（并行，多线程一起建）＋ NOLOGGING（不写重做日志，减少 I/O）。别选 ONLINE（不提速、反而增加开销）、REVERSE（防热点块）、COMPRESS（省空间但费 CPU）。

性能优化（题 35 选 DE，钉死）：redo log 放高性能存储（高频顺序写，放 SSD 显著降低写等待）＋ 临时表空间用 tempfile（不产生 redo，减少 I/O）。注意：索引不是越多越好（B 错）；A、C 实务中也有优化效果但题库未选，考试以本题库为准。

重建索引（题 8 选 BC，钉死有争议）：改变存储选项、移动索引到其他表空间时需重建；按 Oracle 实际"使用索引监测"不需要重建，本题库答案为 BC，考试以本题库为准。

⚠ 核心权衡：索引加速读但拖慢写。凡见"必须建索引""索引越多越好""索引能保安全"都是错误表述。

④ 视图·游标·PL/SQL 对象

视图是虚拟表（只存查询定义，不存数据）：作用是简化复杂查询＋屏蔽敏感数据（题 16 选 AD）。注意两个"不能"：不能加速访问（每次查询都要跑底层 SQL，真加速靠索引或物化视图）、不能代替基表。它的另一个价值是提供多角度观察数据（题 28 选 D）——同一份数据，销售看联系方式、财务看账期、领导看汇总。呼应题 49：视图支持逻辑独立性。

游标四步：声明 → 打开 → FETCH 提取 → 关闭。FETCH 时游标必须已打开，动作是"把当前记录加载到已有变量中"；变量在声明阶段就建好了，不是 FETCH 时才创建（题 11 选 ABD 为"叙述错误"，只有 C 的描述正确）。

游标四属性（题 29 排除 CE）：%FOUND（取到了吗）、%NOTFOUND（没取到，常用于退出循环）、%ISOPEN（打开了吗）、%ROWCOUNT（已取几条）。%ISCLOSE 不存在（陷阱选项）；ROWTYPE 是行类型声明（emp%ROWTYPE）不是游标属性。

触发器时机只有两种（题 17 选 BC）：Before（之前）和 After（之后）。Trigger 是触发器本身的名字，New 是行级触发器里的伪记录（:NEW 新值、:OLD 旧值），都不是时机。

PL/SQL 块能直接跑什么（题 46 选 BC）：DML（INSERT/UPDATE/DELETE/MERGE）和事务控制（COMMIT/ROLLBACK/SAVEPOINT）可直接用；DDL 不能直接跑（TRUNCATE、ALTER TABLE 必须用动态 SQL：EXECUTE IMMEDIATE）。

同义词与命名：同义词＝对象别名，用途是简化语句＋隐藏名称和属主＋提供公共访问（题 32 选 ABC；D"显示名称和所有者"说反了）。表命名四规则（题 41 全选）：同用户不重名、不用保留字、首字符是字母、只能用字母数字下划线（禁空格和单引号）。

⚠ 三个"说反了"陷阱：题 32 的 D（隐藏 vs 显示）、题 46 的 DDL（需动态 SQL）、题 29 的 %ISCLOSE（不存在，应是 %ISOPEN）。

⑤ SQL 语言与 DML

SQL 三分类是本章的分水岭（必背）：DDL 数据定义＝CREATE / ALTER / DROP / TRUNCATE（建改删结构）；DML 数据操纵＝SELECT / INSERT / UPDATE / DELETE / MERGE（增删改查数据）；TCL 事务控制＝COMMIT / ROLLBACK / SAVEPOINT。两道 DML 题对比记：题 20 选项无 MERGE → 选 BC（update、delete）；题 37 选项有 MERGE → 选 BCD（MERGE、UPDATE、DELETE）。两次都排除 COMMIT（TCL）和 CREATE（DDL）。

聚合函数与日期（题 18 选 AD）：日期列可用 MIN/MAX（日期可比较大小，求最早最晚）和 COUNT（统计非空数，任何类型都行）；不能用 SUM/AVG（日期求和求平均无意义）；且 AVG 只接受一个参数，`avg(start_date, end_date)` 语法本身就是错的。

通配符与运算符（题 45 选 BCD）：LIKE 中 % 匹配 0 个或多个字符、_ 匹配恰好一个字符；<> 表示不等于（也可写 !=）。注意 * 在 Oracle 中不是通配符——它只用于 `SELECT *`（选所有列），在 LIKE 里就是字面星号（所以 A 错）。

ORA-00955 名称冲突（题 44 选 ABD）：报"名称已被现有对象使用"，即同 schema 下对象名撞车。解决：换名字、换用户（schema）、删掉旧对象、给旧对象改名。改列名没用——冲突的是表名/对象名不是列名。

能连不能建表（题 30 选 AD）：Oracle 建表需要 CREATE TABLE 系统权限。CONNECT 角色只有 CREATE SESSION（只能登录），RESOURCE 角色才含 CREATE TABLE；只给 create session 也只能登录。注意 C"实例没启动"会导致连不上，与"能连接"矛盾，排除。

⚠ 题 20 与题 37 是同源题，差异只在选项有无 MERGE——看清选项再选，别背死答案。

⑥ Oracle 存储结构与运维

表空间是逻辑、数据文件是物理（题 38 选 AD）：一个表空间可包含多个数据文件；一个数据文件只能属于一个表空间（不能一对多）。类比：表空间像文件夹（逻辑），数据文件像硬盘上的实际存储块（物理）。

扩容三招（题 42 选 ACD）：数据超过表空间大小时，可开启自动扩展、添加数据文件、调大数据文件。"不能用了就重建表空间"是错误做法（会丢数据且没必要）。

bigfile 表空间（题 14 选 BC）：只含一个大容量数据文件＋段空间自动管理（ASSM）＋本地管理（非字典管理）。一个数据库可以有多个 bigfile 表空间（A 错）。价值：简化超大型库的数据文件管理。

三个网络配置文件别搞混（题 15 选 D）：tnsnames.ora（客户端，本地命名＝服务名到主机端口的映射，像手机通讯录）；listener.ora（服务器端，配监听器）；sqlnet.ora（命名方法优先级、超时等参数）。注意 B 选项 "tnsname.ora" 少了个 s，是拼写陷阱。

分区表（题 23 选 ACD）：一张大表按范围/列表/哈希拆成多个物理分区。可用 ALTER TABLE 拆分分区；每个分区可建本地索引（与分区一对一，维护方便，是推荐做法）；可只导出单个分区。B 错——全局索引在分区维护时会失效需重建，不是"便于维护"。

归档日志（题 43 选 ABC）：＝在线重做日志写满后的副本。有了它才能在磁盘故障时做完全恢复；数据库运行于 NOARCHIVELOG（非归档）或 ARCHIVELOG（归档）两种模式。D 说反了——ARCHIVELOG 模式下恰恰就是进行在线日志归档。类比：在线日志像黑板（写完擦掉重写），归档日志像拍照存档。

Oracle 应用两大块（题 24 选 AC）：管理（DBA：安装部署、权限、备份恢复、调优）与开发（PL/SQL 编程：表设计、存储过程、触发器）。安装和调试只是这两个方向里的具体环节。

⚠ 三个名称陷阱：tnsnames.ora（有 s，客户端）vs listener.ora（服务端）；本地索引（好维护）vs 全局索引（分区动就失效）。

⑦ 偏题区（办公软件与编程基础）

本模块 14 题全部跨章混入，与数据库安全无关，标 edge 了解即可。它们来自 Word/Excel/HTML/编译原理/编码风格/多媒体基础等主题，且其中 5 题（题 56–60）与题 1–5 完全重复（同题不同源），已标 dup。

Word 2007 表格（题 1 / 题 25 / 题 56）：两个上下文选项卡——"设计"管样式（边框底纹）、"布局"管结构（插入删除行列单元格、合并拆分、单元格大小＝高宽）。设置行高列宽＝"布局"→"单元格大小"（选 D）。注意"旋转单元格"做不到，只能旋转单元格内的文字方向。

Excel（题 22 / 题 31）：四大能力＝编辑表格、数据管理、设置格式、打印（题 31 全选）。"合并计算"功能既能按位置也能按分类合并，运算也不止求和与均值（还有计数、最大、最小等），所以题 22 说"只能"判错误。

HTML 表格（题 3 / 题 58）：colspan＝横向跨列、rowspan＝纵向跨行、cellpadding＝内边距、width＝宽度。记忆：col＝列、row＝行、span＝跨越。

编译原理（题 4 / 题 59）：符号表记录标识符的名称、类型、作用域、地址，供语义检查和代码生成使用。注意散列表是实现方式，符号表才是概念名称。

编码风格（题 2 / 题 57）：良好风格＝缩进空行、括号明确优先级、代码与注释一致；过短的变量名是坏风格（应见名知义）。

多媒体分类（题 5 / 题 60）：感觉媒体（声音图像）／表示媒体（编码）／表现媒体（输入输出设备：键盘鼠标显示器）／存储媒体（磁盘）／传输媒体（电缆光纤）。鼠标是输入设备 → 表现媒体（选 C）。

运维变更（题 9 选 ACD）：系统变更四要求＝有方案、先审批、后实施、留记录。
