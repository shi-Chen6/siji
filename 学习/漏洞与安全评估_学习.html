1 模块1 漏洞与脆弱性基础

1.1 什么是"漏洞 / 脆弱性"

漏洞（Vulnerability，也叫脆弱性）是系统里"可能被攻击者利用的弱点"——可能是代码缺陷、配置错误，也可能是管理流程的空子。它不是"已经发生的攻击"，而是"容易被攻击的口子"。

生活类比：漏洞像房子墙上的裂缝——现在没进贼，但贼知道从这能钻进来。裂缝就是脆弱性，贼利用裂缝进来就是"被攻击"。

1.2 信息安全漏洞主要表现在哪里（Q11）

漏洞的后果是多维的：系统本身"脆"（设计缺陷）、被"钻空子"非法进入、被各方"打"、内部人"越权"提权。四方面都成立，所以表现为 ABCD 全选。

1.3 安全漏洞的三大来源（Q14）

从系统整体看，漏洞不只是"技术 bug"，还来自人（误操作/被钓鱼）和管理的规划策略执行不到位。漏洞 = 人 + 技术 + 管理，三方面共同构成。

2 模块2 典型漏洞与补丁

2.1 缓冲区溢出：最可靠的方案是打补丁（Q1）

缓冲区溢出是程序没检查输入长度，往固定大小的内存"缓冲区"写了超量数据，覆盖相邻内存，黑客借此植入恶意代码。它的根因是"程序代码本身的缺陷"，所以最可靠的解法是给系统装最新补丁，从代码层面堵洞。

⚠ 必考题：缓冲溢出的"最可靠解决方案"是安装最新补丁，不是防火墙、不是 IDS、不是杀毒——后三者都治标不治本。

2.2 Unicode 漏洞：收紧 cmd 权限可防（Q13）

Unicode 漏洞（经典 IIS 漏洞）利用扩展字符绕过敏感路径、借 cmd.exe 执行系统命令。限制网络用户访问和调用 cmd 的权限，攻击者就拿不到命令行，漏洞利用被阻断。所以限制 cmd 权限是有效防范。

2.3 Apache 安全配置：别暴露版本号（Q5）

Apache 安全配置里，"显示版本号"反而是不安全的——暴露版本等于告诉攻击者你有哪些已知漏洞可打。安全做法：装最新补丁、只启必需服务模块、用专用低权用户/组运行。

3 模块3 漏洞扫描与检测

3.1 脆弱性分析 = 漏洞扫描（Q12）

脆弱性分析技术通俗就叫漏洞扫描技术——自动检测远程或本地系统的安全弱点（配置/补丁/开放端口）。两者是一回事的不同说法。

3.2 端口扫描：预知能否远程登录（Q4）

端口扫描像"敲门"：向目标发探测包，看哪些端口有回应，从而判断开放了哪些服务（如 SSH 22、RDP 3389）。开放即可能远程登录。病毒查杀、包过滤、身份认证都不是这种"预知探测"。

3.3 一次完整的扫描不包括什么（Q17）

完整扫描流程：发现目标 → 搜集信息 → 判断/测试是否存在漏洞。"发现漏洞后能不能解决"是整改环节，不属于"扫描"本身。

3.4 终端防护技术（Q7）

防病毒、补丁管理、漏洞扫描都直接保护终端；"防止非法外联"管的是数据不出网，属边界/防泄露，不直接加固终端本身。

A.正确　B.错误
▸ 显示解析
正确。脆弱性分析技术通俗就叫“漏洞扫描技术”，检测远程或本地系统的安全弱点。脆弱性（vulnerability）=系统可能被攻破的弱点；漏洞扫描就是自动化的脆弱性分析——扫系统配置/补丁/开放端口找弱点。两者是一回事的不同说法。题干说“也被通俗称为”——对。“脆弱性分析=漏洞扫描，换汤不换药。”

4 模块4 恶意代码检测手段

4.1 扫描法：用特征字符串比对（Q16）

扫描法=拿已知病毒的特征字符串（一段独特字节）去比对文件，命中即中毒，包括特征代码扫描法和特征字扫描法。行为检测法看行为、校验和法看哈希变化、比较法看前后差异，都不靠特征字符串。

4.2 特征码 / 行为检测都有风险（Q18）

基于特征码和基于行为的检测，都要在沙箱/监控里"跑"可疑代码才能提取特征或观察行为；一旦逃逸或误判，运行恶意代码就有安全风险。所以"可能带来安全问题"是对的。

4.3 定量 vs 定性评估（Q15）

安全评估：定量=数字打分（精确但参数难量化）；定性=高/中/低分级（易操作）。实际多用定性或定性与定量结合。

【自测】()是用每一种病毒体含有的特征字符串对被检测的对象进行扫描，扫描法包括特征代码扫描法和特征字扫描法。
A.行为检测法　B.扫描法　C.校验和法　D.比较法
▸ 显示解析
选 B。用病毒体特征字符串扫描被检对象的，是“扫描法”（含特征代码扫描法、特征字扫描法）。扫描法=拿已知病毒的特征串（一段独特字节）去比对文件，命中即中毒。行为检测法看行为、校验和法看文件哈希变化、比较法看前后差异，都不靠“特征字符串扫描”。找“特征字符串扫描”→ 扫描法 B。“病毒特征串比对，扫描法最对。”
【自测】基于特征码的扫描技术和基于行为的检测技术都需要执行潜在的恶意代码并分析它们的特征或行为，但是这可能会给系统带来安全问题。()

5 模块5 安全评估闭环与整改

5.1 漏洞挖掘及修复贯穿四阶段（Q10）

漏洞挖掘及修复覆盖信息系统全生命周期：开发（写代码引入）→测试（挖）→上线（加固）→运行（监控修复）。软件著作权管理是法律、第三方安全测试只是测试环节、安全加固是上线后动作，都不覆盖四阶段。

5.2 南网安全基线整改交付物（Q8）

整改要"验证漏洞真修好"，需两种证据：漏洞扫描器渗透测试结果 + 第三方人工渗透测试结果。工具自动化 + 独立人工，避免自查盲区。值班记录、运维文档不证明漏洞已整改。

A.软件著作权管理　B.第三方安全测试　C.安全加固　D.漏洞挖掘及修复
▸ 显示解析
选 D。“漏洞挖掘及修复”贯穿信息系统开发、测试、上线、运行四个阶段。漏洞不是上线才有的，开发阶段写代码就可能引入、测试阶段挖、上线后运维持续修、运行阶段监控。所以“漏洞挖掘及修复”覆盖全生命周期四阶段。软件著作权管理是法律、第三方安全测试只是测试环节、安全加固是上线后动作，都不覆盖四阶段。找“涉及四个阶段”→ 漏洞挖掘及修复。“漏洞挖修贯四段，生老病死都管。”

6 模块6 延伸：硬件接口与综合布线

本章题库还混入了少量"硬件接口 / 综合布线 / 图像录入"题，虽不纯属漏洞评估，但属同一份考卷，一并拿下。

6.1 印刷图片录入设备（Q3）

把纸质图片变数字图像需"采集/输入"设备：扫描仪扫稿、数码相机/数字摄像机拍照。投影仪是输出设备（把电脑画面投大屏），不能录入。

6.2 IDE 设备（Q6）

IDE 是老式并行硬盘/光驱接口。硬盘、CD-ROM 驱动器、刻录机都走 IDE；扫描仪是独立外设，不走 IDE。

6.3 管槽安装规范（Q9）

综合布线里走线管/线槽的要求：路由与建筑基线一致、注意整体布置、"横平竖直"弹线定位。"走最短路由"虽省料但不一定合规，不是基本要求。

A.扫描仪　B.投影仪　C.数字摄像机　D.数码相机
▸ 显示解析
选 B。投影仪不能把印刷图片“录入”计算机；扫描仪、数字摄像机、数码相机都能。印刷图片是纸质的，要变成电脑里的数字图像需“采集/输入”设备。扫描仪扫平面稿；数码相机/数字摄像机拍实物；投影仪是“输出”设备，把电脑画面放大投到屏幕，方向相反。找“不能录入”：A/C/D 都是输入采集类，B 投影仪是放映输出。“录入靠采不靠投，投影只管往外秀。”
【自测】常见的IDE 设备包括：
A.硬盘　B.CD-ROM驱动器　C.扫描仪　D.刻录机
▸ 显示解析
选 ABD。常见 IDE 设备：硬盘、CD-ROM 驱动器、刻录机。IDE（Integrated Drive Electronics）是老式并行硬盘/光驱接口。硬盘、光驱、刻录机都走 IDE；扫描仪是独立外设（并口/USB/SCSI），不走 IDE。排除 C 扫描仪。“IDE 三兄弟：硬盘、光驱、刻录机。”
【自测】管槽安装的基本要求包括()。
A.管槽路由与建筑物基线保持一致　B.注意房间内的整体布置　C.“横平竖直”,弹线定位　D.走最短的路由
▸ 显示解析
选 ABC。管槽安装要求：路由与建筑基线一致、注意整体布置、“横平竖直”弹线定位。管槽（线管/线槽）是综合布线里走网线电线的通道。规范：沿建筑结构走、美观整齐、横平竖直弹线保证平直。D“走最短路由”虽省料但不一定合规（要避开干扰、随建筑走），不是基本要求。排除 D。“管槽安装：基线齐、布置美、横平竖直。”

🃏 速查卡：漏洞与安全评估 20 题核心

① 漏洞基础

  • 漏洞=脆弱性（易被利用的弱点）；表现：脆/进/打/提（ABCD）
  • 漏洞三方面：人、技术、管理（规划策略执行）

② 典型漏洞

  • 缓冲溢出最可靠方案：装最新补丁（非防火墙/IDS/杀毒）
  • Unicode 漏洞：限制 cmd 权限可防
  • Apache：别显示版本号

③ 扫描检测

  • 脆弱性分析=漏洞扫描
  • 端口扫描：探远程登录端口
  • 完整扫描不含"看能否解决"
  • 防止非法外联不护终端（护终端靠杀/补/扫）

④ 恶意检测+评估

  • 扫描法=特征字符串比对
  • 特征码/行为检测都要"跑"代码，有风险
  • 定量虽准参数难，实际用定性或结合
  • 漏洞挖修贯四阶段；整改交付：扫描器+第三方人工

⑤ 延伸硬件

  • 录入图像靠采集（扫描仪/相机/摄像机），投影仪是输出
  • IDE 三兄弟：硬盘、光驱、刻录机
  • 管槽：基线齐、布置美、横平竖直
